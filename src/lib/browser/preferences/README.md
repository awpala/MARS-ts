# Browser preferences

This directory owns the browser's preference records: pane layout, working display settings, engine settings, and the light/dark theme. Each adapter keeps its own schema, defaults, normalization, limits, and storage key, and the [display-preference, workspace, and simulation owners](../../venus/state/README.md) decide when to read and write. Presenters import the limits these adapters enforce (the register-width and Data Segment minimums and the maximum run-speed position), so divider bounds, the slider range, and record validation cannot drift apart; [ThemeToggle](../../venus/components/shell/README.md) saves the theme directly. The engine-settings adapter implements the preference read/write members of the engine's `SettingsHost` and imports only that type; the engine keeps defaults, value parsing, and setting semantics. No adapter holds instance state, a timer, or a subscription, and none stores source text or machine state.

[preferences.ts](preferences.ts) shares the fail-silent JSON read/write mechanics of pane and display preferences, with storage acquired only when an operation runs. Each adapter retains its schema, defaults, normalization, and key. Missing, malformed, blocked, or full storage leaves in-memory preferences usable. Source-library and desktop-recovery writes keep their separate error-reporting paths.

Pane preferences use the versioned `mars-ts:panes:v1` localStorage key. The browser adapter validates numeric values, clamps dimensions to safe lower/fraction limits, and tolerates malformed JSON, denied storage, and quota failures. It exports the lower limits it enforces, `MIN_REGISTER_WIDTH` and `MIN_DATA_SEGMENT_HEIGHT`, so the presenter's divider bounds and the validation of stored records cannot drift apart. The presenter applies viewport-dependent bounds, reads preferences on mount, and writes after a completed pointer gesture or keyboard resize. It preserves the current in-memory layout if persistence is unavailable. These preferences contain no source text or engine state.

Working display settings use the separate `mars-ts:display-settings:v1` key: register-pane visibility (shown by default), Clear all outputs on Go and Prompt to clear all breakpoints (both off by default), label visibility, Data/Text label filters, the LabelsWindow sort state, line numbers, current-line highlighting (on by default, consistent with Java MARS; explicitly saved off choices remain off), hexadecimal value/address display, Data Segment ASCII mode, the legacy run-speed slider position, and the Auto Save toggle (default off). The adapter accepts exact boolean types, sort states 0–7, and integer slider positions 0 through `MAX_SPEED_POSITION` (40, the stored value for maximum speed); malformed or incompatible records use the GUI defaults. Older records without the label filters/sort fields retain their existing preferences and default to both label types with ascending address order. Only supported fields are written, immediately after a preference changes once the view is ready. Source contents, current tabs, selected views, dialogs, and hardware are never persisted by this adapter.

The display-preference adapter owns one field schema for defaults, required-field compatibility, and integer bounds. DisplayPreferences and the workspace’s Auto Save state use its immutable defaults, and the display owner derives its persisted keys from that vocabulary. The original five fields remain required; later fields still receive their previous defaults when absent. Validation retains explicitly stored false values, rejects mistyped or out-of-range fields, and strips unrelated keys.

Engine settings persist one entry per canonical Settings preference key under the `mars-ts:engine-settings:v1:` prefix. This adapter implements the engine's injected preference read/write interface; simulation state passes it to the session host, while the engine retains defaults, value parsing, and setting semantics. Unreadable storage reports no saved value, so the engine uses its defaults, and failed writes are ignored, so settings remain usable for the current session.

The light/dark appearance choice uses `mars-ts:theme:v1`. ThemeToggle saves explicit choices through the theme adapter; blocked or full storage keeps in-memory switching available. The pre-paint script in `src/app.html` runs before application modules load, so it reads the same key as a literal and defaults to light for missing, invalid, or inaccessible values. Change the adapter constant and that script together.

Add an adapter here for a new localStorage preference record, with its key, schema, defaults, and failure behavior. Source and recovery writes keep their separate error-reporting paths in [sources](../sources/README.md) and [session](../session/README.md); deciding when a preference changes belongs to its Venus owner.
