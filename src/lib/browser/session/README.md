# Desktop session recovery record

This directory owns the browser-local desktop recovery record: its storage key and shape, the closed view, tab, and memory-range vocabularies it stores, validation before a record can affect the desktop, atomic writes, and the per-desktop writer that coalesces updates. The [desktop persistence owner](../../venus/state/README.md) decides when to capture and restore and owns the writer's lifetime; Venus state owners, debugger views, the desktop root, and utilities type their selections with the vocabularies exported here. The record's shape borrows two contracts by import: the [editor](../../editor/README.md)'s history-capture type, and the framework-free [RunCheckpoint](../../venus/RunCheckpoint.ts) with its validator, so a stored machine checkpoint is checked by the module that defines it. Source text backups are a separate record in the [source library](../sources/README.md), and preferences have [their own records](../preferences/README.md).

The versioned `mars-ts:desktop-session:v1` recovery record complements source and preference storage. It retains selected views/tabs, caret/viewport, matching editor undo/redo branches, Data Segment navigation, breakpoints, both consoles, and the loaded program's stable machine checkpoint, original source dependencies, and selected label identity (owning file or global table, name, and signed address). The [desktop persistence owner](../../venus/state/README.md) controls when to capture and restore; this adapter validates JSON and performs atomic storage writes. Running execution retains the previous checkpoint and its console buffers. Quota/access write errors propagate to a visible desktop recovery message; malformed reads use ordinary initialization. [ADR 0007](../../../../docs/adrs/0007-desktop-session-recovery.md) defines the boundary and failure behavior.

The desktop-session module also owns the closed vocabularies that the recovery record stores. `MAIN_VIEWS`, `REGISTER_BANKS`, `MESSAGE_TABS`, and `MEMORY_SEGMENTS` list the selectable workspaces, register banks, message consoles, and Data Segment ranges in tab order, with the union types `MainView`, `RegisterBank`, `MessageTab`, and `MemorySegment`. Record validation checks stored values against the same lists, and the Venus state owners and components type their selections with the unions instead of `string` and casts, so adding a tab or range changes one definition.

[DesktopSessionWriter](DesktopSessionWriter.ts) belongs to one desktop. It batches recovery updates in a 200 ms window and caches validated JSON for unchanged detached history and execution snapshots. Page-exit and document-hiding handlers capture and flush current idle state; removal flushes the latest submitted snapshot, then disposes the writer and its cache. The existing recovery format and every undo revision are preserved; source draft backups remain synchronous. Submitted snapshots must remain unchanged after scheduling. The owner may suspend the writer while another owner replaces the stored record, as Import MARS does through the [data adapter](../data/README.md): suspension drops the queued snapshot and ignores submissions, so neither the timer nor the flush on page exit or disposal overwrites the replaced record, and resuming accepts submissions again.

Add to this directory when the recovery record gains a field, vocabulary, or write policy; validate every new field before restoration and keep older records readable. Deciding what to capture, when to restore, and how to report a failed write belongs to the desktop persistence owner.
