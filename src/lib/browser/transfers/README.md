# Browser file transfers

This directory owns files crossing the operating-system boundary: reading a picker selection into an import plan, the ZIP codec that import and Export All Files share, the bodies of source and archive downloads, the browser save picker and download link, the page-focus wait, and the save lifecycle shared by source Export File and the memory-dump dialog. The mounted [transfer components](../../venus/components/transfers/README.md) own native file selection and the export hand-off, the memory-dump dialog owns its own save, and each disposes the `FileDownload` instance it constructs; the [source workspace](../../venus/state/README.md) receives the import plan, checks collisions, and commits. Nothing here reads or writes browser storage: import planning only applies the [source library's](../sources/README.md) name and extension rules, and its skip reasons use the module's shared [error text](../errorMessage.ts). Assembly, runtime console/file I/O, scheduling, and simulator dialogs are not implemented by this download adapter, and MIDI audio belongs to the separate [tone host](../execution/README.md).

Export All Files packages UTF-8 source text as a single `mars-asm-src-files.zip` download with flat, disambiguated entries that keep a recognized `.asm` or `.s` extension (other names receive `.asm`) and no directories. The [ZIP codec](zip.ts) writes stored (uncompressed) entries with CRC-32 checksums and reads single-disk archives with stored or deflated entries, inflating through the browser's built-in `DecompressionStream` and verifying each entry's size and checksum; it never inflates past an entry's declared size, and rejects split and ZIP64 archives and encrypted or otherwise compressed entries with readable reasons. Exports save through the File System Access save picker where the browser offers one (Chromium): `requestSaveTarget` opens it within the user's action and resolves with the chosen file, `canceled`, or undefined when there is no picker or the browser refuses it, and `writeSaveTarget` writes the chosen file, aborting its writable stream when writing or closing fails so the browser discards the pending data and temporary file, then rethrowing the failure. Otherwise `downloadBlob` uses a download link that follows the browser's configured save/prompt behavior and cannot report the prompt's outcome; it removes the anchor at once, releases the object URL in the background a minute later, and resolves once the page is active. That revocation timer belongs to the page rather than to a desktop, because the browser may still read the URL after the click. The [page-focus helper](pageFocus.ts) defines that condition, visible and focused, and resolves as soon as it holds, adding no delay; transfer statuses release through it. Its listeners also belong to the page and are removed when the page next becomes active, so callers recheck their own owner after the wait.

The [import planner](sourceImport.ts) reads a picker selection into a plan without touching storage: directly selected `.asm`/`.s` files keep their filename, ZIP archives contribute their assembly entries under normalized folder paths (directories and `__MACOSX/` metadata are ignored), and every other file or entry is skipped with a reason, including invalid relative paths, names already used earlier in the selection, unreadable or corrupt archives and entries, and sources above the 16 MiB import limit. Text is decoded as UTF-8, like the browser's `File.text()`. `IMPORT_FILE_ACCEPT` is the picker's `accept` value, `.asm,.s,.zip`. [ADR 0003](../../../../docs/adrs/0003-browser-file-workflows.md) defines the distinction between local source commits, recovery backups, and portable exports.

[FileDownload](FileDownload.ts) shares the save-picker, transfer-status, cancellation, page-focus, and late-download-prompt lifecycle between source Export File and the memory-dump dialog. Each mounted owner disposes its instance; it retains no file handle. Both the timed blur guard and the active prompt guard clear the stored release only while they still own it. An older focus continuation cannot clear a replacement guard, and each active prompt releases its transfer at most once. Memory dump bytes come from the framework-free engine, with `.bin` suggested for binary, `.hex` for hexadecimal text and Intel HEX, and `.txt` for ASCII, binary text, and Segment Window. The dump dialog uses `sourceStem` from SourceLibrary to suggest the loaded build’s basename plus the selected segment and format extension, such as `main.text.hex`, independently of the selected editor file. A dump is an OS file transfer, never a source-library commit.

Add an adapter here when it moves bytes between the page and the user's files and owns the browser resources that transfer acquires. Library commits and name rules belong to [sources](../sources/README.md), collision and dirty-buffer policy to the workspace, and memory-dump serialization to the engine.
