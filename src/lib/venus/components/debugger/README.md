# Debugger and console views

This group presents assembled statements, data memory, symbols, register banks, execution location, and message/console output. The [simulation owner](../../state/README.md) and framework-free [RunController](../../RunController.ts) retain execution state and scheduling. Components consume public hardware APIs and controller snapshots; edits report through owner callbacks and existing hardware contracts.

The Labels view preserves the engine's symbol-table ownership: the global table appears under `(global)`, followed by program-local tables headed by their source basenames. These full-width group headings are centered. Filtering and sorting operate within each group, and source filenames come from assembled programs. Rendering does not merge or mutate the underlying tables.

Register and execution views release their subscriptions with their component lifetime. Numeric cell formatting and the console's Clear/Clear All labels, shortcut hints, and derived `aria-keyshortcuts` values are shared through [presentation utilities](../../utils/README.md). The console view renders inline input and reports submission or Stop; simulation state retains the pending syscall resolver, echo rules, and cancellation.

Sized regions come from [layout](../layout/README.md): Text Segment, Labels, and Data Segment use Pane directly, while Registers and Messages compose it through TabbedPane. Debugger views retain their headings, column header cells, table bodies, scrolling, and content selection. The Text Segment and Labels keep their pane heading, any filter controls, and sticky column headings fixed while only their table rows scroll. A layout divider between the Text Segment row and Data Segment sets a parent-owned Data Segment height; when compressed, only the address rows scroll, under sticky column headings. Opening the range selector selects a hidden placeholder bearing the current label, because native selects report no change for a reselected option; choosing the current range therefore resets it to its first page. Shared [controls](../controls/README.md) supply action buttons, including console Clear/Clear All, labeled display and label-filter checkboxes, and the disabled condition-flag group. The register view interprets condition bits; MultiSelect only renders their selection state. Breakpoint cells keep individually named native checkboxes, centered in their cells, without accompanying visible text. Descriptions use [feedback](../feedback/README.md).

[MachineTable](MachineTable.svelte) is the shared frame for the Text Segment, Labels, Data Segment, and Registers/Coproc 1/Coproc 0 tables. It renders the `<table>` root with one sticky heading row, alternating stripes, borders, cell padding, line height, and the bundled highlighting preset, which no other component imports. Callers supply the header cells and `<tbody>` sections and mark highlight roles with `data-highlight`: `pc` and `delay-slot` on Text Segment rows, `memory` on the edited Data Segment word, and `register` on the last-written register row. Callers also mark body cells with two table-owned classes: `numeric` right-aligns monospace numbers and hexadecimal words so they compare digit by digit, and `identifier` bolds the cell naming its row; row addresses are both, while labels and register names are bold but stay left-aligned. The table applies the preset's data and register enablement flags. Cells draw separate borders, right and bottom plus the first cell's left edge and each heading's top edge, so the sticky heading row carries its own border and scrolled rows never show through above it. It has no wrapper element, so scroll containers stay with callers, and callers must not pass CSS custom-property attributes, which would insert one; a bindable rendered height supports Data Segment geometry. Every caller uses the defaults: application-font headings, as in the legacy JTable headers, above monospace preset cells with `2px 4px` padding, normal line height, and one light-theme border fallback. [CellInput](CellInput.svelte) is the borderless value input that fills its cell and inherits the cell's text alignment, with a minimum width that keeps a hexadecimal word visible. Enter commits by blurring, so the owner's native change handler still validates, writes, and reformats the value; Text Segment code, Data Segment words, integer and Coproc 0 registers, and Coproc 1 float/double values use it.

These views compose legacy ExecutePane, TextSegmentWindow, DataSegmentWindow, LabelsWindow, RegistersPane and its register windows, and MessagesPane responsibilities.
