# Debugger and console views

This group presents assembled statements, data memory, symbols, register banks, execution location, and message/console output. The [simulation owner](../../state/README.md) and framework-free [RunController](../../RunController.ts) retain execution state and scheduling. Components consume public hardware APIs and controller snapshots; edits report through owner callbacks and existing hardware contracts.

The Labels pane's Close icon button hides it through the parent-owned persisted display preference, clearing Show Labels Window in both the toolbar and Settings. Its close affordance shares the source tabs' themed hover styling and tooltip through CloseButton.

The Labels view preserves the engine's symbol-table ownership: the global table appears under `(global)`, followed by program-local tables headed by their source basenames. These full-width group headings are centered. Filtering and sorting operate within each group, and source filenames come from assembled programs. Rendering does not merge or mutate the underlying tables. The selected Labels row is highlighted in tandem with its segment destinations. Both the Label and Address cells expose the desktop navigation tooltip and activate the same destination: text labels select and reveal both their assembled instruction and the corresponding word in the Data Segment `.text` range, with keyboard focus on the instruction; data labels choose the nearest legacy range, restore the page containing the address, and center and focus its word cell, including the containing word for byte labels. The parent simulation owner retains the selected label identity across Edit/Execute remounts and localStorage recovery with the loaded program; filename, case-sensitive name, and address distinguish local/global symbols and aliases. Restoring Execute reveals selected rows without changing keyboard focus. Clicking the same label again through either cell clears selection in Labels and the destination tables; distinct labels retain their own row selection even when they share an address or occupy one word. Navigation restores visibility even after paging or compressing and scrolling the Data Segment, and does not change the PC. Register Name entries use a pointer cursor and expose the descriptions from the corresponding legacy integer, exception, and floating-point register windows through the shared themed tooltip.

Register and execution views release their subscriptions with their component lifetime. Assembly and Reset clear Data Segment write highlighting after data initialization, as the legacy run actions do; assembly writes are not left highlighted. Single-step and timed execution observe runtime writes; unlimited Go does not introduce new write highlights. Observed stores and backstep writes reveal their destination range/page and center its word without selecting a label or moving keyboard focus. Manual data-memory edits update values without introducing an execution highlight. Changed assembled text words retain the legacy self-modifying-code exception: even manual Code edits and unlimited execution reveal the changed word in Data Segment. Backstep preserves the undone instruction's delay-slot display context. Assembly and Reset restore the first `.data` page, and paging clamps to the legacy user/kernel address boundaries. Register banks retain independent last-write highlights, select the bank receiving a stepped/timed or backstep write, and clear all highlights on assembly/reset. Completion retains the last executed instruction highlight until backstep, assembly, or Reset changes the execution location; errors retain the faulting instruction. The exact stop address is saved in the browser checkpoint and restored without guessing from the next PC. The controller captures the executed address from simulator stop notices, so a terminating syscall or a jump off text does not highlight an unexecuted following row. Numeric cell formatting and the console's Clear/Clear All labels, shortcut hints, and derived `aria-keyshortcuts` values are shared through [presentation utilities](../../utils/README.md). The console view renders inline input and reports submission or Stop; simulation state retains the pending syscall resolver, echo rules, and cancellation.

Sized regions come from [layout](../layout/README.md): Text Segment, Labels, and Data Segment use Pane directly, while Register Banks and Messages compose it through TabbedPane. Debugger views retain their headings, column header cells, table bodies, scrolling, and content selection. The Text Segment and Labels keep their pane heading, any filter controls, and sticky column headings fixed while only their table rows scroll. PC tracking holds the opening page through its last fully visible instruction, then centers each current row below the column headings, with native scroll limits pinning the first and last pages. Assembly and Reset restart this opening-page behavior; tracking preserves horizontal position and keyboard focus. A layout divider between the Text Segment row and Data Segment sets a parent-owned Data Segment height; when compressed, only the address rows scroll, under sticky column headings. Opening the range selector selects a hidden placeholder bearing the current label, because native selects report no change for a reselected option; choosing the current range therefore resets it to its first page. Shared [controls](../controls/README.md) supply action buttons, including console Clear/Clear All, labeled display and label-filter checkboxes, and the disabled condition-flag group. The register view interprets condition bits; MultiSelect only renders their selection state. Breakpoint cells keep individually named native checkboxes, centered in their cells, without accompanying visible text. Descriptions use [feedback](../feedback/README.md).

[MachineTable](MachineTable.svelte) is the shared frame for the Text Segment, Labels, Data Segment, and Registers/Coproc 1/Coproc 0 tables. It renders the `<table>` root with one sticky heading row, alternating stripes, borders, cell padding, line height, and the bundled highlighting preset, which no other component imports. Callers supply the header cells and `<tbody>` sections and mark highlight roles with `data-highlight`: `pc` and `delay-slot` on Text Segment rows, `memory` on the edited Data Segment word, and `register` on the last-written register row. Label navigation separately sets `data-selected="true"` on the selected Labels row, destination instruction row, and memory word; this selection remains visible across the tables when focus moves and does not represent a machine write. Callers also mark body cells with two table-owned classes: `numeric` right-aligns monospace numbers and hexadecimal words so they compare digit by digit, and `identifier` bolds the cell naming its row; row addresses are both, while labels and register names are bold but stay left-aligned. The table applies the preset's data and register enablement flags. Cells draw separate borders, right and bottom plus the first cell's left edge and each heading's top edge, so the sticky heading row carries its own border and scrolled rows never show through above it. It has no wrapper element, so scroll containers stay with callers, and callers must not pass CSS custom-property attributes, which would insert one; a bindable rendered height supports Data Segment geometry. Every caller uses the defaults: application-font headings, as in the legacy JTable headers, above monospace preset cells with `2px 4px` padding, normal line height, and one light-theme border fallback. [CellInput](CellInput.svelte) is the borderless value input that fills its cell and inherits the cell's text alignment, with a minimum width that keeps a hexadecimal word visible. Enter commits by blurring, so the owner's native change handler still validates, writes, and reformats the value; Text Segment code, Data Segment words, integer and Coproc 0 registers, and Coproc 1 float/double values use it.

[RegisterBanksPane](RegisterBanksPane.svelte) groups the Registers, Coproc 1, and Coproc 0 tabs in the sidebar controlled by the Register Banks switch. Its name distinguishes the containing pane from the Registers tab. These views compose legacy ExecutePane, TextSegmentWindow, DataSegmentWindow, LabelsWindow, RegistersPane and its register windows, and MessagesPane responsibilities.
