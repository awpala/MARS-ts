# Shared interaction feedback

This group owns reusable loading status, hover descriptions, keyboard-shortcut presentation, and pane-level error text. Callers supply labels and trigger content. These components do not require desktop context, dispatch commands, or own application preferences.

The loading spinner supplies an accessible status while its parent owns loading state and placement. The shared Tooltip component is the single owner of standard description lifetimes: delayed opening on hover, immediate dismissal when the pointer leaves the trigger (including movement into the tooltip), keyboard-visible focus, viewport placement, explicit dismissal, and cleanup. Standard descriptions do not receive pointer events or extend their own hover lifetime. Ordinary pointer activation dismisses the description; binary toggle controls explicitly keep it open through clicks while their trigger remains hovered, with state-dependent descriptions updated in place. Selection and navigation buttons keep ordinary action behavior. Content scrolling caused by a toggle keeps its description positioned while the trigger remains under the pointer; other scroll dismissal, Escape, window blur, and resize behavior remain in place. Controls declare the click policy through props rather than installing their own tooltip event handlers. The tooltip text is optional: missing or empty text suppresses the tooltip and attaches no trigger listeners, so a control can always render through Tooltip without deciding whether it has a description. The floating description takes its padding, border, background, shadow, and type from the application stylesheet's shared popup surface, which the source editor's instruction help also uses. Keyboard hints render the caller's shortcut string as theme-aware keycaps while preserving an accessible text alternative, splitting it with the shared [shortcut notation](../../utils/commands/README.md).

[InlineAlert](InlineAlert.svelte) renders pane-level failure text as a `role="alert"` paragraph in the themed error color, and nothing while the message is empty. The owning component keeps the message and decides when it clears; the register banks and Data Segment use it for rejected edits. Dialog variants keep their own dialog-scoped alert, which is intentionally neutral in color, so the two presentations are not interchangeable.

The source editor's keyword reference documents are the rich-content exception: their token hit-testing, scrollable reference entries, placement, and hover interaction remain owned by the editor view. They do not use the standard short-description Tooltip component.

The desktop persistence alert renders the caller-selected backup, autosave, or settings persistence error with a themed warning background. Its caller owns error precedence and clearing; empty text renders nothing.

These browser presentation primitives support the menus, toolbar, debugger, dialogs, and transfer controls described in the [Venus guide](../../README.md). They replace browser-native title hints without moving command policy into feedback. Add reusable status or descriptive interaction here; feature-specific messages and decisions stay with their view or state owner.
