# Interactive controls

This group owns native action buttons, new-tab resource links, single and grouped checkbox selections, radio choices, tab strips, numeric sliders, and binary switches with their accompanying labels. Controls are independent of desktop context and engine instances. Panes, menus, and dialogs compose them while retaining their workflows; values and selection stay with callers. Controls contain no file, execution, theme-selection, or storage policy.

[Button](Button.svelte) renders a native button with caller-supplied text or icon content and optional themed tooltip and shortcut hints. Native attributes and event handlers pass through, including disabled and pressed states, accessible names, and form attributes. The default type is `button`; form actions explicitly request `submit` or `reset`. It adds no layout wrapper or default visual style, so callers provide classes and surrounding layout. An optional attachment supports element-local focus behavior and follows the native element's lifetime. Tooltips preserve any caller-supplied description IDs and own their existing dismissal and cleanup behavior. Binary toggle callers explicitly opt into `keepTooltipOnClick`; ordinary actions and selection/navigation buttons keep click dismissal even when they expose `aria-pressed`. Toggle and SelectorToggle opt in, and ToolbarButton opts in only when it receives a boolean toggle value. Hover descriptions remain visible through toggle clicks and update in place. All standard descriptions disappear immediately when the pointer leaves their trigger, even when moving into the tooltip itself. These pointer rules are implemented once in Tooltip; controls only declare their click policy.

The shell's ToolbarButton specializes Button with compact icon geometry, toolbar colors, pressed presentation, and label-based tooltips. Dialog actions, menu commands, console Clear/Clear All and input actions, clipboard transfers, debugger navigation, and tab triggers use the same native button contract. Their workflow policy remains outside the generic control.

CloseButton shares the compact SVG Close icon, theme-aware hover border and background, accessible description, and optional shortcut hint between source tabs, the Labels pane, and the Program Arguments clear action. Its fixed 18-pixel button fits within pane heading text height, preserving the Labels and Text Segment heading alignment. Callers own the close, hide, or clear action, confirmation, and visibility state; the component registers no keyboard command.

[LinkedResource](LinkedResource.svelte) renders a native anchor to an external or bundled resource. It always opens the destination in a separate tab with `rel="noopener noreferrer"`, so following it leaves the current desktop session in place. Callers resolve the destination, for example through `asset` for bundled files, and supply the visible content; native anchor attributes and events pass through. Like Button, it adds no default visual style, accepts an optional element attachment, and shows an optional themed tooltip whose description ID is combined with any caller-supplied `aria-describedby`. Callers own any "opens in a new tab" wording, and icon-only links must supply an accessible name. The shell's GitHub link and Help's attribution and license links reuse it instead of repeating the new-tab attributes.

[SelectorToggle](SelectorToggle.svelte) renders a checkbox inside its clickable label. Bind `checked` for editable boolean preferences, or pass `checked` and `onchange` for derived selections; the callback receives the new value after any binding is updated. Disabled controls retain native keyboard and accessibility behavior. Optional accessible names, description IDs, and a label attachment preserve abbreviated captions and caller-owned descriptions. An optional `tooltip` follows the Button and Toggle convention: label hover or checkbox focus shows a themed description whose ID is combined with any caller-supplied `aria-describedby`. The Execute Labels Data/Text filters use it rather than composing Tooltip around the control. Label classes control placement, and `--selector-gap` controls the space between the box and text.

[RadioSelector](RadioSelector.svelte) renders one native radio choice with its clickable label. Callers share a unique group name and bind the selected string across choices; native grouping retains arrow-key navigation. The optional callback receives the selected value after the binding updates. Layout and disabled state remain caller-owned; the control does not apply settings or access storage.

[MultiSelect](MultiSelect.svelte) composes SelectorToggle into an accessible labeled group. Stable string or numeric option values determine membership; changes emit a new array in option order. It supports group-wide and per-option disabled states, an optional caption description, per-option descriptions, horizontal or vertical layout, abbreviated accessible labels, and empty content. The Open dialog binds its workspace-owned filenames to the group; the register pane projects condition bits into an editable group and writes the changed flag itself. Neither consumer duplicates checkbox-array membership logic. Breakpoint cells retain their compact, individually named inputs because they have no accompanying visible text.

[PaneTabs](PaneTabs.svelte) renders keyed choices for pane and source-document variants, preserving caller-owned selection and content lifetimes. Default triggers use native Button controls with `aria-pressed` selection state and normal browser focus traversal; the strip does not implement an ARIA tablist or arrow-key navigation. Optional action and control snippets allow document close buttons or an inline rename input without adding file workflows to the strip. The layout group's TabbedPane composes the strip with a body snippet, while the editor's source-tab view owns temporary rename text and focus restoration. These shared semantics stay in one strip rather than separate generic tab-item components.

[Slider](Slider.svelte) wraps a native range input with a visible label, bindable numeric value, configurable bounds and step, and optional formatted value text exposed to assistive technology. Native disabled state and events pass through. The shell's SpeedSlider supplies the MARS position range and [run-speed conversion](../../utils/runSpeed.ts); the desktop applies and persists that position.

[Toggle](Toggle.svelte) composes Button into a labeled binary switch with a bindable value, disabled state, optional description, and decorative track content. It owns keyboard activation and thumb presentation. The shell's ThemeToggle supplies the sun/moon icons, restores the pre-paint theme on mount, and updates the document theme and separate browser preference. The generic switch does not access storage or choose an application theme.

Add controls here when they own a focused input-and-label interaction, preference switch, or reusable native link behavior. Shell components compose controls into application chrome; feature-specific selection rules and execution behavior remain with their callers.

Toggle keeps a neutral track by default for settings such as light/dark appearance. Its active variant uses distinct on/off fills and a contrasting thumb for enabled/disabled presentation, as used by register-bank sidebar visibility. Both variants retain the same native keyboard and switch semantics; callers own values and persistence.
