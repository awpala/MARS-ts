# Interactive controls

This group owns native action buttons, single and grouped checkbox selections, tab strips, numeric sliders, and binary switches with their accompanying labels. Controls are independent of desktop context and engine instances. Panes, menus, and dialogs compose them while retaining their workflows; values and selection stay with callers. Controls contain no file, execution, theme-selection, or storage policy.

[Button](Button.svelte) renders a native button with caller-supplied text or icon content and optional themed tooltip and shortcut hints. Native attributes and event handlers pass through, including disabled and pressed states, accessible names, and form attributes. The default type is `button`; form actions explicitly request `submit` or `reset`. It adds no layout wrapper or default visual style, so callers provide classes and surrounding layout. An optional attachment supports element-local focus behavior and follows the native element's lifetime. Tooltips preserve any caller-supplied description IDs and own their existing dismissal and cleanup behavior.

The shell's ToolbarButton specializes Button with compact icon geometry, toolbar colors, pressed presentation, and label-based tooltips. Dialog actions, menu commands, console Clear/Clear All and input actions, clipboard transfers, debugger navigation, and tab triggers use the same native button contract. Their workflow policy remains outside the generic control.

[SelectorToggle](SelectorToggle.svelte) renders a checkbox inside its clickable label. Bind `checked` for editable boolean preferences, or pass `checked` and `onchange` for derived selections; the callback receives the new value after any binding is updated. Disabled controls retain native keyboard and accessibility behavior. Optional accessible names, description IDs, and a label attachment preserve abbreviated captions and caller-owned tooltips. Label classes control placement, and `--selector-gap` controls the space between the box and text.

[MultiSelect](MultiSelect.svelte) composes SelectorToggle into an accessible labeled group. Stable string or numeric option values determine membership; changes emit a new array in option order. It supports group-wide and per-option disabled states, horizontal or vertical layout, abbreviated accessible labels, and empty content. The Open dialog binds its workspace-owned filenames to the group; the register pane projects condition bits into a disabled group. Neither consumer duplicates checkbox-array membership logic. Breakpoint cells retain their compact, individually named inputs because they have no accompanying visible text.

[PaneTabs](PaneTabs.svelte) renders keyed choices for pane and source-document variants, preserving caller-owned selection and content lifetimes. Default triggers use native Button controls with `aria-pressed` selection state and normal browser focus traversal; the strip does not implement an ARIA tablist or arrow-key navigation. Optional action and control snippets allow document close buttons or an inline rename input without adding file workflows to the strip. The layout group's TabbedPane composes the strip with a body snippet, while the editor's source-tab view owns temporary rename text and focus restoration. These shared semantics stay in one strip rather than separate generic tab-item components.

[Slider](Slider.svelte) wraps a native range input with a visible label, bindable numeric value, configurable bounds and step, and optional formatted value text exposed to assistive technology. Native disabled state and events pass through. The shell's SpeedSlider supplies the MARS position range and [run-speed conversion](../../utils/runSpeed.ts); the desktop applies and persists that position.

[Toggle](Toggle.svelte) composes Button into a labeled binary switch with a bindable value, disabled state, optional description, and decorative track content. It owns keyboard activation and thumb presentation. The shell's ThemeToggle supplies the sun/moon icons, restores the pre-paint theme on mount, and updates the document theme and separate browser preference. The generic switch does not access storage or choose an application theme.

Add controls here when they own a focused input-and-label interaction or preference switch. Shell components compose controls into application chrome; feature-specific selection rules and execution behavior remain with their callers.
