# Interactive controls

This group owns native and icon-only action buttons, new-tab resource links, single and grouped checkbox selections, radio choices, native dropdowns, tab strips, numeric sliders, and binary switches with their accompanying labels. Controls are independent of desktop context and engine instances. Panes, menus, and dialogs compose them while retaining their workflows; values and selection stay with callers. Controls contain no file, execution, theme-selection, or storage policy.

[Button](Button.svelte) renders a native button with caller-supplied text or icon content and optional themed tooltip and shortcut hints. Its `variant` selects the base look: `plain`, the default, leaves all styling to the caller; `bordered` adds the themed border and surface (`--theme-border` and `--theme-surface`, with the light-mode fallbacks `#929eaa` and `#f8f8f8`); and `outlined` adds only the themed border. Clipboard, the run-speed steppers, and Select all/none share `bordered`, which unifies the border and surface those controls once styled separately, and the console actions use `outlined`. Dark mode is token-driven and unchanged by the variants. DialogActions keeps its own equivalent child-selector styling for the buttons it lays out. Native attributes and event handlers pass through, including disabled and pressed states, accessible names, and form attributes. The default type is `button`; form actions explicitly request `submit` or `reset`. It adds no layout wrapper; callers provide resting appearance and surrounding layout. The shared control applies the theme hover background and accent border to enabled actions, including dialog buttons, console actions, menus, transfers, and debugger navigation. Disabled and ARIA-disabled buttons do not highlight. Pressed or selected buttons keep their solid fill by default, so selected pane and source tabs do not re-highlight; IconButton retains its explicit selected-state hover, and switches retain their state-specific track colors. An optional attachment supports element-local focus behavior and follows the native element's lifetime. Every Button renders through Tooltip, which treats missing or empty text as no tooltip and attaches no trigger listeners, so a button never branches on whether it has a description. Tooltips preserve any caller-supplied description IDs, joined with the tooltip's ID by the shared `describedBy` helper from the [DOM utilities](../../utils/dom/README.md), and own their existing dismissal and cleanup behavior. Binary toggle callers explicitly opt into `keepTooltipOnClick`; ordinary actions and selection/navigation buttons keep click dismissal even when they expose `aria-pressed`. Toggle and SelectorToggle opt in, and IconButton opts in only when it receives a boolean `pressed` value. Hover descriptions remain visible through toggle clicks and update in place. All standard descriptions disappear immediately when the pointer leaves their trigger, even when moving into the tooltip itself. These pointer rules are implemented once in Tooltip; controls only declare their click policy.

[IconButton](IconButton.svelte) is the square icon-only specialization of Button, shared by toolbar actions, close affordances, and compact pane controls such as Data Segment paging and restore. It requires an accessible label and an icon source that the [icon components](../icons/README.md) render as a theme-aware glyph, a full-color bundled image, or a bundled SVG tinted with the surrounding text color; it comes in three sizes (small, medium, and large, the toolbar size, which is the default), shows one dimming for the disabled state, and keeps a transparent resting border that shows the accent border on hover. Its tooltip defaults to the label unless a caller supplies other text, and a shortcut hint is display only. A boolean `pressed` value turns it into a toggle with selected styling and a tooltip that stays through clicks. The icon is decorative because the label names the button; callers own what activation does, and the command catalog describes toolbar actions with the same icon sources. Dialog actions, menu commands, console Clear/Clear All and input actions, clipboard transfers, debugger navigation, and tab triggers use the base Button directly. Their workflow policy remains outside the generic control.

Button and IconButton also accept a caller-owned momentary highlight, using the same theme colors as hover without adding toggle semantics. The desktop uses it to acknowledge enabled function-key and console-clearing shortcuts.

CloseButton is a thin IconButton with the compact SVG Close mark, so source tabs, the Labels pane, and the Program Arguments clear action share its theme-aware hover border and background, accessible description, and optional shortcut hint. Its small 18-pixel size fits within pane heading text height, preserving the Labels and Text Segment heading alignment. Callers own the close, hide, or clear action, confirmation, and visibility state; the component registers no keyboard command.

[LinkedResource](LinkedResource.svelte) renders a native anchor to an external or bundled resource. It always opens the destination in a separate tab with `rel="noopener noreferrer"`, so following it leaves the current desktop session in place. Callers resolve the destination, for example through `asset` for bundled files, and supply the visible content; native anchor attributes and events pass through. Like Button, it adds no default visual style, accepts an optional element attachment, and always renders through Tooltip, so an optional themed tooltip's description ID is combined with any caller-supplied `aria-describedby`. Callers own any "opens in a new tab" wording, and icon-only links must supply an accessible name. The shell's GitHub link and Help's attribution and license links reuse it instead of repeating the new-tab attributes.

[SelectorToggle](SelectorToggle.svelte) renders a checkbox inside its clickable label. Bind `checked` for editable boolean preferences, or pass `checked` and `onchange` for derived selections; the callback receives the new value after any binding is updated. Disabled controls retain native keyboard and accessibility behavior. Optional accessible names, description IDs, and a label attachment preserve abbreviated captions and caller-owned descriptions. An optional `tooltip` follows the Button and Toggle convention: label hover or checkbox focus shows a themed description whose ID is combined with any caller-supplied description IDs by the shared helper. The Execute Labels Data/Text filters use it rather than composing Tooltip around the control. Label classes control placement, and `--selector-gap` controls the space between the box and text.

[RadioSelector](RadioSelector.svelte) renders one native radio choice with its clickable label. Callers share a unique group name and bind the selected string across choices; native grouping retains arrow-key navigation. The optional callback receives the selected value after the binding updates. Layout and disabled state remain caller-owned; the control does not apply settings or access storage.

[Select](Select.svelte) wraps a native single-choice dropdown with a bindable string value and caller-provided option snippet. Native attributes and events pass through, and no wrapper interferes with an enclosing label or disabled fieldset. Field and option backgrounds, foregrounds, borders, hover, keyboard focus, and disabled colors are centralized here using the desktop theme tokens; the native arrow and popup retain the document's color scheme and browser keyboard behavior. The memory-dump dialog composes it with DialogField for both segment and format selection. The Data Segment pane also uses it for memory-range selection, passing native style attributes to retain its compact chrome surface. Its native event handlers use `currentTarget` for placeholder arming and restoration, so the control needs no element-reference API or memory-navigation policy. Options, descriptions, and selection policy stay with callers.

[MultiSelect](MultiSelect.svelte) composes SelectorToggle into an accessible labeled group. Stable string or numeric option values determine membership; changes emit a new array in option order. It supports group-wide and per-option disabled states, an optional caption description (the caption always renders through Tooltip), per-option descriptions, horizontal or vertical layout, abbreviated accessible labels, and empty content. The Open dialog binds its workspace-owned filenames to the group; the register pane projects condition bits into an editable group and writes the changed flag itself. Neither consumer duplicates checkbox-array membership logic. Breakpoint cells retain their compact, individually named inputs because they have no accompanying visible text.

[SelectAllNone](SelectAllNone.svelte) supplies the shared bulk-selection button pair for the Open dialog and condition flags. It emits a fresh array of all available values or an empty array, disables actions whose selection already holds, and uses theme-aware hover feedback only for enabled buttons. Its two buttons use Button's `bordered` variant. Callers retain selection ownership and domain updates; placement and optional button-padding customization remain with the surrounding layout.

[PaneTabs](PaneTabs.svelte) renders keyed choices for pane and source-document variants, preserving caller-owned selection and content lifetimes. Default triggers use native Button controls with `aria-pressed` selection state and normal browser focus traversal; the strip does not implement an ARIA tablist or arrow-key navigation. Optional action and control snippets allow document close buttons or an inline rename input without adding file workflows to the strip. The layout group's TabbedPane composes the strip with a body snippet, while the editor's source-tab view owns temporary rename text and focus restoration. These shared semantics stay in one strip rather than separate generic tab-item components.

[Slider](Slider.svelte) wraps a native range input with a visible label, bindable numeric value, configurable bounds and step, and optional formatted value text exposed to assistive technology. Native disabled state and events pass through. The shell's SpeedSlider supplies the MARS position range and [run-speed conversion](../../utils/execution/runSpeed.ts); the desktop applies and persists that position.

[Toggle](Toggle.svelte) composes Button into a labeled binary switch with a bindable value, disabled state, optional description, and decorative track content. It owns keyboard activation and thumb presentation. The shell's ThemeToggle supplies the sun/moon icons, restores the pre-paint theme on mount, and updates the document theme and separate browser preference. The generic switch does not access storage or choose an application theme.

Add controls here when they own a focused input-and-label interaction, preference switch, or reusable native link behavior. Shell components compose controls into application chrome; feature-specific selection rules and execution behavior remain with their callers.

Toggle keeps a neutral track by default for settings such as light/dark appearance. Its active variant uses distinct on/off fills and a contrasting thumb for enabled/disabled presentation, as used by register-bank sidebar visibility. Both variants retain the same native keyboard and switch semantics; callers own values and persistence.
