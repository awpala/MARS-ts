# Desktop dialog composition

This directory owns workflow-specific dialog presentation. Each variant reads the nearest [desktop context](../../context/README.md), renders one workflow through [Modal](Modal.svelte), and delegates actions to the existing [state owner](../../state/README.md). Source opening, deletion, the import summary, saving, close-all confirmation, the Clear all breakpoints confirmation, dirty closure, search, Help, and prompted syscall input have independent views. The workspace, search, and simulation owners retain their rules, pending data, and cancellation behavior.

[DesktopDialogs](DesktopDialogs.svelte) selects workspace dialogs through a registry checked against the workspace's modal type. Help, console input, and syscall-dialog views observe their separate owners. A change of workspace variant mounts the corresponding component; save-target changes also remount the save shell to preserve initial focus between queued saves.

Open derives a case-insensitive lexicographic filename listing from the saved sources, using exact spelling only to break ties between names that differ solely in case. Sorting affects presentation without mutating storage or editor tab order; checkbox selection continues to use the exact source identity. The generic MultiSelect renders the ordered choices and updates the workspace-owned filename selection; opening and deletion remain workspace actions.

Open places the reusable SelectAllNone control at the left of its action footer, opposite the right-aligned Open, Delete, and Cancel buttons. Bulk selection updates the same workspace-owned selection as individual checkboxes, and enabled footer buttons share theme-aware hover highlighting. DialogActions accepts an optional leading snippet for this layout without taking ownership of selection or workflow rules.

The import summary lists the plan's sources with their archive and whether each replaces a saved source or matches an open buffer with unsaved edits, then every skipped file or entry with its reason. Import is disabled when nothing is importable or an edited buffer would be overwritten; the workspace still rechecks on commit. A separate transfer-status variant renders the desktop's pending import or export status as a native modal dialog with the shared spinner: it has no close control, ignores Escape, makes the rest of the page inert, and restores focus when the desktop clears the status.

Invalid renames have a focused warning variant showing the validation failure and the latest valid filename. Inline tab editing and Save As Rename share this presentation through the workspace; neither the warning nor the modal shell validates names or mutates source records.

Modal owns native dialog lifetime, the accessible heading, backdrop and Escape dismissal, focus containment, and focus restoration. It accepts a content snippet and has no knowledge of workflow variants. Shared action and field components provide compact, theme-aware layouts through snippets while preserving native form submission, input bindings, validation, and labeling. A shared error component renders the owning state's current workflow failure as a dialog-scoped `role="alert"` paragraph only while that message is nonempty; the source-file variants pass the workspace's file error, and the workspace retains that text and decides when it clears. Dialogs use the generic Button and selection components from [controls](../controls/README.md); submit actions explicitly choose the native submit type. Variant-specific lists, warnings, and conditional choices stay with their own view.

These are browser compositions of the file actions, search, Help, and syscall input presentation formerly coordinated by the legacy Venus desktop, following [ADR 0002](../../../../../docs/adrs/0002-port-fidelity.md) and the [browser file workflows](../../../../../docs/adrs/0003-browser-file-workflows.md). Add a variant for a distinct workflow and reuse the shell, layouts, and error alert; keep domain rules in their state owner rather than adding a switch to Modal.

The memory-configuration variant translates `mars/venus/SettingsMemoryConfigurationAction.java` using the engine’s existing layout catalog. Its draft and opening selection live only for the mounted dialog. `SimulationState` owns application, reassembly, and persistence; `DesktopState` owns modal visibility so keyboard commands respect the dialog. Address preview and Reset never mutate the machine.

Memory configuration vertically centers the selectors beside the address table, stacking only on narrow screens. The configuration area scrolls within the viewport-limited modal while its action footer remains visible. Modal exposes body display/overflow custom properties for dialogs that own an internal scrolling region; other variants retain the default scrolling body.

The memory-dump variant translates `mars/venus/FileDumpMemoryAction.java`. DesktopState owns its visibility and command gate: a successfully loaded program with idle execution is required, including data-only programs and terminated runs. The mounted dialog composes the shared [Select](../controls/Select.svelte) control for theme-aware segment and format choices. It suggests the loaded build’s source basename without its assembly extension, followed by the segment and output extension (for example, `main.text.hex`); selecting a different editor file does not rename dumps of the loaded machine. The mounted dialog owns draft segment/format selections, errors, and its [FileDownload](../../../browser/FileDownload.ts) lifecycle. [Engine encoders](../../../engine/dump/README.md) calculate ranges and bytes; the browser save picker chooses the OS destination, with a download fallback elsewhere. Cancellation preserves selections, failed writes abort and show an alert, and success closes the modal. Empty memory presents a closeable message rather than an invalid selector.

The exception-handler variant translates `mars/venus/SettingsExceptionHandlerAction.java`. Its enable/disable switch, plain-text filename, and nested single-source Browse selection are transient drafts. Browse appears only for the custom choice and is disabled while inclusion is off. Both radio choices are dimmed and disabled while off. Browse lists saved library entries in Open order and preselects the current draft handler if present; canceling Browse preserves the outer draft. Cancel, close, or Escape on the outer dialog discards all drafts. SimulationState persists changed enablement and selected filename independently, so toggling inclusion never clears the file and a selection made before disabling can still be saved. Both values are restored after reopening or application reload. DesktopState keeps this dialog available during execution and includes it in the modal guard; it never changes loaded code. See [ADR 0013](../../../../../docs/adrs/0013-exception-handler-workflow.md).

Exception Handler also offers the bundled SPIM default handler, separately from custom-library Browse. Open default `exceptions.s` in editor closes without applying the draft and opens a protected reference; the dialog states this explicitly. The SPIM source includes startup for a global `main`, assumes the default layout, and retains MARS warnings for unsupported `.set` directives. The editor’s lock banner offers Copy to new file for customization. The toolbar’s final runtime action opens the same exception dialog, and Memory Configuration follows the ASCII display toggle.

Exception-handler inclusion gates both dimmed radio choices and the custom Browse button without clearing the selected source. The custom Browse/filename row is absent for SPIM. The default-source preview remains available while automatic inclusion is disabled; its filename is bold monospace in the action label.

`SyscallDialog` presents services 50–59 independently of the console popup preference. Confirmation offers Yes/No/Cancel; input retains an unrestricted draft so the engine determines parsing and truncation; message variants display the canonical text with a type-specific heading. Each request remounts the shell for initial focus. Cancel resumes with the legacy result, while window close/Escape/backdrop returns confirmation -1 or input null. Explicit Stop requests termination and releases the pending operation. There is no console echo. SimulationState owns the resolver and clears it once on response or teardown. [ADR 0014](../../../../../docs/adrs/0014-random-and-dialog-syscalls.md) records these adaptations.
