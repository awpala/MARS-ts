# Desktop shell composition

This group composes application-wide menus, toolbar command groups, footer status, and repository navigation. The Footer renders a parent-resolved current-view filename, optional focused-editor caret position, optional execution status, and breakpoint suspension annotation; it owns no source selection or machine state. The desktop coordinator resolves everything except the caret position, which the root adds because it depends on which element has focus, and the footer's five props are unchanged. The group composes generic buttons, new-tab links, selection boxes, and range and binary-switch primitives from [controls](../controls/README.md). Menus and the toolbar consume only the shared [command context](../../context/README.md) capability and never the full desktop context: dispatch, enablement, and pressed state for commands, plus the live display toggles (the toolbar's Display settings group and the top of the Settings menu) and the engine-setting checkboxes only the Settings menu offers, all built by the coordinator from the Settings catalog. Their remaining props are the bound sidebar-visibility, clear-outputs, and breakpoint-clearing-prompt preferences on the menu bar and the line-number, run-speed, and speed-visibility values on the toolbar. Reusable dropdowns, buttons, and groups accept records, callbacks, or snippets. They do not save sources, assemble programs, or own simulator execution.

Command metadata and shortcut hints come from [presentation utilities](../../utils/README.md); menu and toolbar availability stays synchronized through the same live capability. The toolbar renders its actions and toggles through the controls group's IconButton, the icon-only specialization of the generic Button, which supplies the toolbar icon geometry, pressed/disabled styling, native semantics, and a tooltip that defaults to the action label; the command catalog names each action's icon as a theme-aware glyph or a full-color bundled image, which the [icon components](../icons/README.md) render from `static/icons`, and the breakpoint toggle swaps to its suspended glyph while breakpoints are disabled. The execution group ends with Exception Handler, and the Display settings group ends with Memory Configuration; both dispatch the same commands as their Settings entries. The Tools menu lists the legacy tools as disabled entries. Native menu dismissal belongs to the menu bar. SpeedSlider specializes Slider with MARS speed mapping and binds to the desktop's preference owner. The toolbar renders it only in Execute; hiding it in Edit retains the speed value. It presents one evenly spaced stop per distinct speed, with maximum only at the final stop, and stacks granular Plus/Minus buttons immediately to the right. The slider and its step buttons fit within the same fixed 29-pixel row height as toolbar actions, so showing the speed controls never enlarges that row. Its view positions map to the existing saved legacy setting domain, with the persisted maximum taken from the display-settings adapter, and its Plus/Minus steps use Button's `bordered` variant. ThemeToggle specializes Toggle with sun/moon content masked from bundled icons, adopts the pre-paint choice on mount, and updates the document theme; it saves its independent browser preference through the [theme preference adapter](../../../browser/README.md), which owns the storage key and storage-failure handling. RegisterBanksToggle supplies the Register Banks caption covering the Registers, Coproc 1, and Coproc 0 tabs, show/hide descriptions, and Toggle’s active/inactive fills, and binds to the desktop’s persisted sidebar visibility immediately before Theme. Theme retains neutral track semantics. The GitHub link composes the generic LinkedResource with its themed tooltip and accessible name, so it opens a separate tab; its current-color mark masks the external static GitHub SVG through the icon group's MaskIcon. SpeedSlider's Plus/Minus steps use the same MaskIcon, and their controls supply accessible names. Shared hover descriptions and keycaps come from [feedback](../feedback/README.md).

Toolbar button opacity changes are delayed briefly to avoid a whole-toolbar flash when a single step quickly enters and leaves the running state. Native disabled state and command guards change immediately; longer operations still show their disabled appearance.

This composes the menu, toolbar, action, and run-speed presentation formerly coordinated by legacy VenusUI and RunSpeedPanel, with browser appearance and repository controls. The [Venus guide](../../README.md) records the adaptations. Add shell-wide command composition here and domain-free input semantics under controls; put workflow-specific content in its feature group and execution rules in state or the framework-free controller.
