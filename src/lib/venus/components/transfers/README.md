# Browser text and file transfers

This group owns browser interactions that move exact source text across the application boundary. Clipboard controls either copy supplied code with local success/failure feedback or delegate transfer into a new editor source. File import owns the native picker and asynchronous reads of selected sources and ZIP archives; export owns single/all download actions and collision-free download filenames. Each also has a `mars` variant for the whole-application data file: Import MARS reads one `mars-ts-data.json`, and Export MARS downloads one. All hold the desktop's blocking transfer status while they work.

Mounted file behaviors register capabilities with the nearest [desktop context](../../context/README.md) and release their registrations during teardown. The [workspace owner](../../state/README.md) retains source snapshots, local-library persistence, import collision confirmation, and dirty-buffer protection. Clipboard and file readers ignore late completion after disposal. Each nonempty import selection supersedes earlier reads, including their error paths, so an older result cannot replace a newer pending import. The picker offers the legacy assembly extensions, `.asm` and `.s`, plus `.zip`. The [browser import planner](../../../browser/README.md) turns the selection into the sources to import, with archive entries under their folder paths, and the skipped files and entries with their reasons; the importer hands that plan to the workspace, which always shows the summary before anything is committed. The importer covers the desktop with "Waiting for file selection…" from the moment it opens the native picker, since the browser reports nothing until the picker closes. The picker's outcome sets the text: a selection reads "Attempting import…" while it is read, and the `cancel` event reads "Canceling import…"; the two never follow each other. A selection delivered without the picker, as tests do, starts at "Attempting import…". Browsers that report neither outcome release the spinner two seconds after the picker returns focus. Every status is released as soon as the page is focused and visible, adding no delay. It releases the status and waits a tick before the summary opens, so the status dialog restores focus first and the summary returns focus to the same place. Export File prepares the file, opens the browser's save picker within the user's action where one exists, and covers the desktop with "Waiting for save location…" while it is open; the outcome sets "Exporting…" while the file is written or "Canceling export…" for a cancellation. Without a picker, "Exporting…" covers the download-link hand-off, and a save prompt that takes focus within three seconds afterwards brings the status back until focus returns; teardown removes that guard, and a hand-off that settles after teardown installs none. A save-picker write that fails is aborted by the [download adapter](../../../browser/README.md) and reported through the desktop, which ignores reports once disposed; the browser write itself is not canceled by unmounting. Every status is released as soon as the page is active. Export File uses the [export filename rule](../../utils/sources/README.md), which keeps a recognized extension in lowercase, so an exported `.s` source imports back as `.s`, and gives other names `.asm`. Clipboard actions compose the generic [Button](../controls/Button.svelte) in its `bordered` variant, which supplies native activation, the shared border and surface, and themed tooltips from [feedback](../feedback/README.md); transfer state and asynchronous completion handling remain here.

The `mars` variants reuse the same picker, status, and save lifecycle with the browser [data adapter](../../../browser/data/README.md). The importer mounts a second hidden picker, single-file and filtered to `.json`, registered as Import MARS; it reads the selection into a reading that is either a schema-conforming payload with its summary or a list of problems, and hands it to the desktop's [Import MARS owner](../../state/README.md), which shows the confirmation or rejection and performs the replacement. A reading is never an exception: malformed, nonconforming, oversized, and unreadable files all arrive as problems to display. The exporter first asks desktop persistence to flush, so the stored session is current, then captures the mirrored storage keys, validates the capture, and saves it as `mars-ts-data.json` through the shared save lifecycle; stored data that does not conform is reported through the desktop instead of being written to a file. [ADR 0017](../../../../../docs/adrs/0017-portable-mars-data.md) governs these two commands.

These are browser adaptations of source-file workflows and code transfer, governed by [ADR 0003](../../../../../docs/adrs/0003-browser-file-workflows.md). Add browser transfer mechanics here; keep saved-source policy and editor mutations with the workspace, and use [dialog variants](../dialogs/README.md) for confirmation presentation.
