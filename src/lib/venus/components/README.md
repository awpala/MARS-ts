# Venus browser components

This directory owns browser presentation and element lifetimes for the Venus desktop. The top-level [root](../VenusUI.svelte) composes these views and owns the lifetime of the [desktop state](../state/README.md). Separate state owners manage the editor, machine, execution controller, pending syscall input, file workflows, and persisted preferences. Component access to that state follows one policy. Feature components that coordinate with a desktop owner (dialogs, file transfers, the debugger views, and the editor views) read the nearest desktop through the [desktop context](../context/README.md) and follow live owner fields instead of receiving each persisted value as a prop. The shell's menus and toolbar read only the narrower command capability of that context, which now also exposes the live setting toggles, and never the owners themselves. Generic controls, layout, and feedback components stay prop-driven with no context, and a few view-owned or null-safe values remain documented props: the pane and divider geometry the root owns, the machine, controller, and snapshot handed to the Execute and register panes, the shell's bound preferences, and the footer's content. The engine never imports this directory.

Components are grouped by their presentation responsibility and imported directly from that group. The root contains this guide, not a barrel or compatibility wrappers.

| Group                            | Responsibility                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| [shell](shell/README.md)         | Application menus, grouped toolbar commands, embedded preferences, and repository navigation                               |
| [controls](controls/README.md)   | Native and icon-only buttons, new-tab resource links, checkbox selections/groups, tab strips, sliders, and binary switches |
| [layout](layout/README.md)       | Reusable pane shells and adjustable dividers                                                                               |
| [editor](editor/README.md)       | Source rendering, editing interactions, highlighting, and document tabs                                                    |
| [debugger](debugger/README.md)   | Execution, register, memory, label, and console presentation                                                               |
| [feedback](feedback/README.md)   | Shared loading status, tooltip interactions, keyboard hints, and pane-level error text                                     |
| [transfers](transfers/README.md) | Clipboard and browser file-transfer behaviors                                                                              |
| [dialogs](dialogs/README.md)     | Modal rendering, shared form layouts and error alerts, and focused workflow variants                                       |
| [icons](icons/README.md)         | Theme-aware, conditional, and current-color rendering of the bundled static icons                                          |

Controls, layout, and feedback remain independent of desktop context and feature views. Feature components may compose those primitives, the icon components, and transfer controls; they leave source and machine policy with their state owners. Dialog variants, like the debugger and editor views, consume context, while the Modal shell and its field/action layouts remain snippet-driven and the shared error alert receives its message from the variant.

Pane provides the generic sized region and content renderer, used by the execution segments through the debugger's SegmentPane frame and specialized by TabbedPane for tabbed editor, register, and message regions. TabbedPane is generic over its tab type, so callers pass a closed vocabulary such as the register banks or message consoles and receive the selected tab with that same type; it supplies a body snippet and optional tab-strip actions. Its body snippet receives the selected tab; the caller decides which content stays mounted. CSS custom properties control pane dimensions without reaching through component-scoped styles. The controls group's generic tab strip supports both pane tabs and scrollable nested document tabs, with stable keys and per-document action snippets. Selecting a document or closing it delegates to the editor owner; the tab strip does not create or dispose buffers.

Dropdowns render ordered groups of command or checkbox records, with separators between nonempty groups. Menu bars own native-details dismissal within their own element and use an instance-specific details group name. Toolbar groups accept content snippets, the shared icon-only IconButton owns labeling and pressed/disabled presentation, and the icon components reference bundled SVG files rather than drawing inline artwork. The menu and toolbar adapters resolve their command records and setting toggles through the same desktop capability, so reusable controls do not know how to save files or execute a machine, and the shell stays independent of the individual owners.

Generic Button preserves native events, accessible attributes, explicit form submission, and optional tooltip descriptions, and centralizes theme-aware hover background and border colors for enabled actions. It also offers a `variant`: `plain` leaves all styling to the caller, `bordered` adds the themed border and surface, and `outlined` adds only the border. Disabled controls and selected tabs retain their resting appearance; switches and icon-button toggles keep their specialized state colors. IconButton is the square icon-only specialization, shared by the toolbar, close affordances, and compact pane controls such as Data Segment paging; CloseButton is a thin IconButton. Menus, dialog actions, console Clear/Clear All, transfers, debugger actions, and tab triggers reuse the base control. LinkedResource is the corresponding anchor primitive: it always opens its destination in a separate tab without an opener reference, passes native anchor attributes through, and accepts the same optional tooltip; it, Button, and SelectorToggle compose their description IDs with a shared helper from the [DOM utilities](../utils/dom/README.md). The repository link and Help's attribution and license links reuse it; callers keep any new-tab wording.

Selection controls share a native checkbox and clickable label through [SelectorToggle](controls/SelectorToggle.svelte). Panes, dropdown selections, and source dialogs retain their state through bindings or change callbacks; accessible descriptions, disabled states, and label spacing stay consistent. Like Button and Toggle, it accepts an optional tooltip; the Labels Data/Text filters use it rather than composing Tooltip around the control. Every tooltip-capable control routes through Tooltip unconditionally, which attaches no listeners when its text is empty, rather than branching on whether a description exists.

The controls group owns generic Slider and Toggle primitives. Shell specializations supply MARS run-speed formatting and theme content. The desktop retains the speed position for persistence and engine assignment; ThemeToggle owns its document theme, restoring the pre-paint choice on mount, and saves its separate preference through the [browser theme adapter](../../browser/README.md). Generic controls do not access engine or browser persistence state.

MultiSelect composes labeled checkboxes for editable and read-only groups. The Open dialog binds filenames to its vertical group, while the register pane presents condition bits as a disabled horizontal group. The shared control owns membership updates and ordering; file workflows and bit interpretation stay with their consumers.

Source rendering owns its hover and scroll state while delegating edits and selection updates. The editor publishes its textarea to the workspace while mounted and clears it on removal, so the workspace can focus and select source for find/replace and source navigation; scroll offsets are stored directly on the workspace. Execution and register panes read parent-owned hardware through public APIs and release their existing subscriptions. The Execute view composes the Text Segment, Labels, and Data Segment panes, which share one per-view model for navigation, formatting, memory access, and write observation; the [debugger guide](debugger/README.md) describes its ownership. Their tables share a machine-table frame that owns stripes, the sticky heading row, cell spacing, and preset highlight colors, plus a value input that commits on Enter; each view keeps its cells, highlight choices, and edit handling. The message pane renders output and inline input while simulation state retains the pending resolver and syscall completion rules. Adjustable separators own pointer gesture state and emit size/commit callbacks; their owner clamps viewport geometry and persists the result.

Loading status is a separate component owning the accessible label and continuously rotating spinner. The desktop owns its overlay positioning, initialization, visibility, and pending reveal-frame cleanup.

Tooltip owns hover and keyboard-focus descriptions, viewport placement, accessible description IDs, dismissal, and cleanup. Pointer activation and loss of window focus dismiss it; mouse focus does not retain a tooltip after the pointer leaves. Tooltip's text is optional, and the themed floating surface it shares with the source editor's instruction help comes from the application stylesheet. KeyboardShortcut renders the same command hints as theme-aware keycaps. The repository link follows the theme toggle and opens GitHub in a new tab through LinkedResource, drawing its mark with the icon group's current-color MaskIcon. Clipboard has copy-code and transfer-to-file variants, with exact source text and safe asynchronous feedback.

Modal renders the shared dialog shell and owns focus containment, dismissal, and restoration. [Dialog variants](dialogs/README.md) compose that shell with workflow-specific content, shared field/action layouts, and a shared error alert for the owner's current failure message; pane-level failures use the feedback group's InlineAlert, while the dialog alert keeps its neutral dialog presentation. DesktopDialogs selects the active workspace variant through a typed registry; it does not implement forms or workflow conditionals.

FileImporter owns file-picker reads and releases its command registration on unmount; FileExporter has single/all variants and releases or replaces its registration when unmounted or its variant changes. The toolbar and menus invoke those registered capabilities through their existing commands.

This is a browser composition of the responsibilities historically implemented by `mars/venus/VenusUI.java`, `MainPane.java`, `MessagesPane.java`, `ExecutePane.java`, the Text Segment, Data Segment, and Labels windows, the register windows, and the editor UI. The [module guide](../README.md) records behavior and adaptations, and [ADR 0002](../../../../docs/adrs/0002-port-fidelity.md) governs fidelity.

Add a component when it owns a cohesive view, interaction lifetime, or reusable rendering contract. Place it with the responsibility it extends; retain engine algorithms in the engine, workflows in their state owners, and desktop composition in VenusUI.

The [memory-dump dialog](dialogs/DumpMemoryDialog.svelte) delegates range discovery and serialization to the engine and shares the browser save lifecycle with FileExporter through FileDownload. It renders the existing Modal, DialogField, DialogError, and DialogActions; no separate modal framework or source-library record is introduced.
