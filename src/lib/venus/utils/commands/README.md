# Command and settings catalogs

This directory owns the presentation definitions that menus, the toolbar, the keyboard binding, and the shared toggles read instead of repeating command and setting lists. It adapts the menu structure, shortcuts, labels, and hover descriptions of `mars/venus/VenusUI.java`. The definitions describe presentation and matching; execution and enablement belong to the desktop through the [command context](../../context/README.md), and adding an entry here does not implement a command.

[actions.ts](actions.ts) is the action catalog: file, edit, run, breakpoint, console, help, and memory-configuration actions, each with a label, stable command identifier, optional shortcut text, and optional toolbar icon (a theme-aware glyph or a full-color bundled image, both files under `static/icons`). `actionFor` and `requireAction` look an action up by command, the latter treating an unknown command as a programming error. The Help actions derive from the Help article catalog. `menus` and `toolbarGroups` give the displayed order, and `unavailableTools` lists the Tools entries that stay disabled. An action marked `unavailable` is a deliberately disabled command, and `noRepeat` marks shortcuts whose held key must not repeat (New, Close, and Close All), which the keyboard binding reads rather than keeping its own command list. `keyboardAction` resolves a key event against the displayed shortcut text, accepting Meta as the platform equivalent of Ctrl and requiring modifiers to match exactly. `physicalKeyAction` resolves the Alt/Option+letter and Alt/Option+Shift+letter shortcuts by physical key, derived from the same displayed shortcuts and requiring Shift to match the chord exactly, so macOS dead-key and composition characters cannot hide them; New, Close, Close All, and Clear All are the current matches.

[shortcuts.ts](shortcuts.ts) is the shortcut notation. It splits text such as `Ctrl+S` or `Alt+N / Option+N` into alternative chords, and converts it to an `aria-keyshortcuts` value that names Ctrl as Control and Option as Alt and omits repeated chords. Keycaps, keyboard matching, and the accessible shortcut therefore come from one definition.

[settings.ts](settings.ts) is the Settings catalog. `engineOptions` lists the engine preferences the desktop exposes, in Settings menu order, with each label, legacy hover description, optional toolbar glyph, and whether changing it invalidates a loaded assembly. `SimulationState` consults that flag when a setting changes, so a new option declares its invalidation in one place instead of in a controller list; changing delayed branching is handled first, because it reassembles loaded code as `SettingsDelayedBranchingAction.java` does. `toggleSpecs` lists the toolbar toggles and, for those marked for Settings, the checkbox entries at the top of the menu; each names the display preference or engine setting it flips, and the desktop coordinator builds its live toggles from them. Engine options with no toolbar glyph become the Settings-only checkboxes. The file also defines the shapes of the live toggles (`DisplayToggle` and `EngineMenuToggle`) that the command context hands to menus and the toolbar, so those views render a toggle's label, description, value, and inversion request without reaching its owner. The file also holds the browser-specific Clear all outputs on Go entry ([ADR 0008](../../../../../docs/adrs/0008-clear-outputs-on-go.md)), the memory-configuration description, and the Settings entries whose dialogs are not implemented.

Add a command, shortcut form, or setting here when menus, toolbar, or keyboard handling would otherwise each repeat it. Per-command behavior stays in the desktop coordinator, a setting's engine semantics stay in the engine's `Settings`, and the live state of a toggle stays with its preference owner. The [Venus guide](../../README.md) retains the keyboard policy.
