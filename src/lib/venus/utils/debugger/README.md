# Debugger table rules

This directory owns the pure rules behind the Execute tables and the register tables: how an integer cell is displayed, which Data Segment range and page shows an address, and how the Labels window orders its rows. Its consumers are the [debugger components](../../components/debugger/README.md), principally the Execute view model and the Data Segment, Labels, and register panes. It ports the range, paging, and sort algorithms of `mars/venus/DataSegmentWindow.java` and `mars/venus/LabelsWindow.java`; the components keep rendering, focus, and subscriptions.

[tableCells.ts](tableCells.ts) formats a machine word in the selected base. Hexadecimal delegates to the engine's `Binary` API, decimal addresses are unsigned, and register and data values stay signed, so the register and memory tables agree. Enter-to-commit for machine values belongs to the debugger's shared cell input, and parsing an edited value stays with the engine.

[memoryView.ts](memoryView.ts) holds the Data Segment's geometry (sixteen rows of eight words per page) and its range rules. It computes the current base of every selectable range, with `$gp` and `$sp` following the registers' present values; the first address of a page from a range and relative page offset; the lowest and highest page starts, which keep user and kernel pages inside their legacy address boundaries (linked kernel-text labels share the text selector with user instructions); and the offset after paging by a number of bytes. `locateAddress` chooses the range and page that show an address: text addresses use the text range, kernel data and memory-mapped addresses their own, and anything else the nearest eligible base at or below the address, with ties keeping the earlier range and no eligible base keeping the current one. Pages keep the range's boundaries, so a label is not placed in the first row of its page.

`segmentBases` and `readDisplayWord` are the helpers that receive the machine, always as an argument. `readDisplayWord` reads a word for display without notifying observers, shows the live statement's code for kernel text, and shows zero for an unreadable address. When self-modifying-code protection would refuse a text-segment read, it enables that setting without persistence for the single read and restores it in a `finally` block, as `DataSegmentWindow` does solely for display; no other path through this directory changes machine configuration.

[labelSort.ts](labelSort.ts) is the eight-state sort of the Labels window. `nextLabelSortState` maps the current state and clicked column to the next state, remembering each column's direction when the sort switches columns as `LabelsWindow` does; `labelSortColumn` and `labelSortDescending` read a state; and `compareLabels` orders unsigned addresses or case-insensitive names. The desktop persists the integer state with the display preferences, which accept states 0 through 7.

Add a rule here when two debugger views need the same display, paging, or ordering decision. Keep DOM measurement and scrolling in the [dom](../dom/README.md) helpers, view-model state and write observation in the Execute view, range and layout persistence in the [browser adapters](../../../browser/README.md), and engine memory semantics in the [hardware module](../../../engine/hardware/README.md).
