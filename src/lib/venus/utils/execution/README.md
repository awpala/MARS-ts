# Run-speed and run-outcome rules

This directory owns pure rules about assembling and running a program: how assembly notices list sources, how the speed slider maps to the engine's run speed, and what the console and views show when a Go or Step settles. They port presentation algorithms from `mars/venus/RunSpeedPanel.java`, the write-following rule of the register and memory windows, and the completion messages of `mars/venus/RunGoAction.java` and `mars/venus/RunStepAction.java`. Execution itself stays with the framework-free [RunController](../../RunController.ts) and the engine.

[runSpeed.ts](runSpeed.ts) converts a legacy slider position (0 through 40) to instructions per second, or to `UNLIMITED_SPEED`, the sentinel that ports `RunSpeedPanel.UNLIMITED_SPEED` and is not a rate. It derives the label from the same conversion that configures the machine, so the two cannot disagree. The browser slider presents one evenly spaced stop per distinct speed, with maximum only at the final stop, and `RUN_SPEED_MAX_POSITION` is that endpoint; the persisted maximum position, `MAX_SPEED_POSITION`, is owned by the [display-settings adapter](../../../browser/README.md) because it validates stored records.

`observesWrites` is the legacy window rule for following writes. A simulator start notice begins an observed run when its speed is not unlimited or when it executes a single step, and the register and memory windows follow writes only during such runs. `RunController` records the result of each notice and exposes it as `isObservingWrites()`. Because the simulator notifies observers in reverse registration order, a handler for the start notice must classify that notice with `observesWrites(notice)` rather than read the controller's flag, which may not yet reflect it. Handlers for later register and memory writes read the flag, so a pane mounted during an observed run follows writes immediately.

[runOutcome.ts](runOutcome.ts) describes a settled Go or Step from the controller's final state: the text appended to Mars Messages and to Run I/O, the console tab to select, and the register bank to select. Errors report the diagnostics, select Mars Messages and the Coproc 0 bank; normal and null-instruction termination, user termination, and a Go that pauses at a breakpoint or by request each have their own message and console tab, derived from those actions. The function returns a description and changes nothing; `SimulationState` applies it, appending Run I/O text through its single capped path.

Add a rule here when it converts between slider, simulator, and display values or decides what a settled run shows, and callers outside one state owner need it. The controller keeps run state and scheduling, the simulation owner keeps appending and tab selection, and the debugger panes keep their own subscriptions and highlighting.

[buildFileNameList](buildFileNameList.ts) ports `RunAssembleAction.buildFileNameList`: it lists prepared virtual source names in assembly order, counts preamble and filename characters but not separators, wraps after names that exceed 60 counted characters, and ends with a blank line. RunController supplies names only after source preparation succeeds; SimulationState appends the notice before assembly diagnostics. The [Java workflow probe](../../../../../tests/oracle/exception-handler/README.md) pins exact bytes.
