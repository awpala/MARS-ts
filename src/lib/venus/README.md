# Venus desktop interface

This module presents the MARS desktop arrangement in Svelte: menus and toolbar, Edit/Execute panes above Messages/Run I/O, and the persistent register sidebar. It adapts `mars/venus/VenusUI.java`, `MainPane.java`, `MessagesPane.java`, `ExecutePane.java`, `RunSpeedPanel.java`, and the register-window classes. The root route mounts the desktop directly without a launch screen.

The desktop owns an Editor and interaction state per component instance. Source open, new, download save, unsaved close, undo/redo, clipboard, find/replace, and print actions operate on source buffers. Modals use the current document's native dialog element for focus containment and restore focus on teardown. [Browser file adaptations](../../../docs/adrs/0003-browser-file-workflows.md) describe downloads, directory limits, and Exit.

The browser mounts one `Globals` machine and one `RunController` per desktop. The register pane consumes that machine's integer and coprocessor registers rather than maintaining independent hardware. It refreshes from controller revisions and register subscriptions, using nonnotifying reads. Integer cells retain the original edit restrictions; floating cells accept decimal values through the Java floating-point compatibility adapter or exact hexadecimal bit patterns. Editing is suspended during execution. Condition flags display the real coprocessor state.

Assemble supplies the canonical assembler with the current editor buffer, or all open buffers when that setting is selected. Include lookup uses the same explicitly opened virtual files; missing includes produce diagnostics rather than searching a directory. Unsaved source is assembled directly. Source edits invalidate execution until reassembly. The Execute pane displays actual machine statements, source locations, global/local symbols, and paged memory. Source links return to the matching editor line; labels navigate to text or data addresses. Breakpoint checkboxes feed the controller's simulator call, with Run actions to clear or suspend them. Memory words can be inspected in decimal, hexadecimal, or ASCII and edited while execution is stopped.

Go, Step, Backstep, Pause, Stop, and Reset call the translated Venus action coordinator. Register, memory, PC, and delayed-slot highlights use the bundled editorial presets. Reset reassembles the retained tokenized programs, restoring initialized memory and registers. Run speed preserves the legacy 41 slider positions, including unlimited positions 36–40. The browser supplies cooperative scheduling; stopping releases pending input and wakes timed execution. Console input supports Enter, submission, or automatic completion at a syscall's character limit. Optional input dialogs stay in the same tab. Cancel/backdrop closure requests Stop and returns the current typed buffer, preserving the canonical numeric parse-error behavior for empty input. Popup input is echoed with the original user-input prefix. On teardown the desktop unsubscribes, requests Stop, awaits execution through controller disposal, and releases scheduling resources.

Working display preferences and engine settings persist in localStorage, with in-memory operation when storage is unavailable. Source and machine state are not persisted. A keyboard-accessible vertical divider changes the register panel width; an analogous horizontal divider changes the source/messages split. Both support pointer dragging, keyboard arrows, Home, and End. The layout adapter restores saved dimensions with viewport limits. Menus close on outside clicks or Escape. Controls remain disabled until hydration attaches handlers. Tools, File → Dump Memory, exception-handler configuration, and memory-configuration dialogs remain disabled; no complete desktop parity is claimed. Core browser scenarios exercise assembly, step/backstep, breakpoints, console/modal input, pause/stop, reset, all-open sources, includes, and floating-register edits; results are reported by the validation run rather than inferred from component compilation.

SVG toolbar controls use [prepared assets](../../../static/README.md); the favicon remains the original MARS ICO. Derived from MARS, copyright 2003–2013 Pete Sanderson and Kenneth Vollmar, under the [MIT license](../../../MARSlicense.txt).

Editor typography and syntax colors come from [editor-preset.json](../editor/editor-preset.json); runtime table colors and fonts come from [highlighting-preset.json](highlighting-preset.json). These static imports are bundled at build time and do not use localStorage. Change the JSON and rebuild to change the editorial presets. Runtime table presets style register, text, and data views. The corresponding Editor/Highlighting dialogs are intentionally absent. “Assemble all open files in editor” supplies current open buffers, including unsaved edits. Tools remain disabled until core assembly and execution are validated.
