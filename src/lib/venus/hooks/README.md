# Venus keyboard lifetimes

This directory owns reusable component-lifetime event bindings. `useKeyboard` registers a window keydown handler on mount and removes it on unmount through Svelte's event helper. It ignores composition and AltGraph unless the caller explicitly recognizes an app shortcut through the modified-input predicate; already-handled events stay ignored, and repeats are ignored unless the caller opts in. Callers explicitly match accepted inputs and decide when to prevent their default behavior. An enabled getter reads current state without retaining an initialization-time snapshot.

The desktop binding reads the nearest [desktop context](../context/README.md), resolves commands using the shared [command metadata](../utils/commands/README.md), and applies the same availability rules as menus and toolbars. All defined shortcuts use one capture-phase handler across every focused surface, including text inputs, console output, and the page body. Matching events cancel browser defaults before command availability and modal guards are checked; disabled commands and active dialogs therefore do not fall through to browser actions. Alt+N / Option+N creates a new source buffer and matches the physical N key to cancel dead-key composition; held-key repeats are captured without creating additional buffers. Alt+L / Option+L clears both console outputs and also matches physical L, including layouts that emit a different Option character. Alt+W / Option+W closes the current source through the normal save/discard/cancel workflow, matches physical W when Option emits a different character, and ignores held-key repeats. Alt+Shift+W / Option+Shift+W runs Close All, opening the same confirmation as the File menu and toolbar before each dirty buffer's save/discard/cancel decision; it also matches physical W with Shift and ignores held-key repeats. The physical Alt/Option+letter matches (currently New, Close, Close All, and Clear All) are derived from the displayed shortcut text of the command catalog rather than a list kept here, and the catalog's `noRepeat` marker, not a command list in the binding, decides which commands ignore held-key repeats (New, Close, and Close All). The explicit physical Alt/Option shortcuts are matched in the window capture phase even when the platform flags their events as composing or AltGraph, preventing shortcut characters from reaching the source textarea; genuine Ctrl+Alt/AltGraph input remains editor input. Source tab close buttons show the same shortcut in their tooltips. The desktop binding also installs a dirty-source unload guard, which reads the workspace's published list of unsaved names, and releases it on unmount. Source hover help uses the generic hook only for Escape dismissal.

Enabled function-key commands and the console Clear and Clear All shortcuts also request a brief highlight of their matching button; disabled and modal-blocked commands do not. The desktop owns and clears the highlight timer, independently of command execution and toggle state.

This is a browser integration boundary. It owns neither editor nor machine state, and imports no process-wide mutable state. Element-specific interactions such as divider arrows and textarea Tab insertion stay with their components rather than installing global shortcuts. Browser-reserved combinations can be handled only when the browser delivers their events to the document.
