# Venus keyboard lifetimes

This directory owns reusable component-lifetime event bindings. `useKeyboard` registers a window keydown handler on mount and removes it on unmount through Svelte's event helper. It ignores composition, AltGraph, already-handled events, and repeats unless the caller opts in. Callers explicitly match accepted inputs and decide when to prevent their default behavior. An enabled getter reads current state without retaining an initialization-time snapshot.

The desktop binding reads the nearest [desktop context](../context/README.md), resolves commands using the shared [command metadata](../utils/README.md), and applies the same availability rules as menus and toolbars. All defined shortcuts use one capture-phase handler across every focused surface, including text inputs, console output, and the page body. Matching events cancel browser defaults before command availability and modal guards are checked; disabled commands and active dialogs therefore do not fall through to browser actions. Alt+N / Option+N creates a new source buffer and matches the physical N key to cancel dead-key composition; held-key repeats are captured without creating additional buffers. Alt+L / Option+L clears both console outputs and also matches physical L, including layouts that emit a different Option character. The desktop binding also releases its dirty-source unload guard on unmount. Source hover help uses the generic hook only for Escape dismissal.

This is a browser integration boundary. It owns neither editor nor machine state, and imports no process-wide mutable state. Element-specific interactions such as divider arrows and textarea Tab insertion stay with their components rather than installing global shortcuts. Browser-reserved combinations can be handled only when the browser delivers their events to the document.
