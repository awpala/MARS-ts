# Source mapping and tokenization

This group owns source-line mapping, token records/lists/types, lexical scanning, includes, and equivalence substitution. It ports `SourceLine.java`, `Token.java`, `TokenList.java`, `TokenTypes.java`, and `Tokenizer.java` from [mars/assembler](../../../../../_legacy-app/mars/assembler/). `JavaCharacter` adapts the consumed JDK character operations using the generated JDK 21 BMP table. The [assembler guide](../README.md) places these contracts within the complete passes.

## Representations and identity

| Representation | Contract                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| `SourceLine`   | Capture the original filename while retaining the caller-owned program reference and original line number |
| `Token`        | Retain type identity, value, current source position, and original program/line mapping                   |
| `TokenList`    | Own an ordered token sequence and processed line; shallow clones share token objects                      |
| `TokenTypes`   | Preserve canonical category identities and classification precedence using injected real lookup services  |

Source positions are Java-compatible one-based line/column numbers where exposed by the translated APIs. Numeric token classification uses signed 32-bit values from `Binary`; character classification works on UTF-16 code units. Supplementary characters are not silently treated as one Java `char`. Source/token state belongs to a program or tokenizer, not a global editor session.

## Stateful scanning and source services

Whole-program `Tokenizer.tokenize()` initializes the equivalence dictionary, expands includes, tokenizes source, and accumulates mapped diagnostics. Its source program retains the mutable `SourceLine` list while separately snapshotting plain source strings. `.eqv` processing can subsequently replace mapped lines without changing that aliasing contract. Diagnostics retain their original persistence; public line overloads preserve the original routing to instance or caller lists.

The dedicated instruction-example entry point skips equivalence substitution. Production instruction initialization uses fresh tokenizer instances so an invalid example cannot contaminate another definition's diagnostics. Callers must not treat all line overloads as interchangeable stateless helpers.

`TokenizerSourceHost` supplies path separator/absolute/parent operations and synchronous access to explicitly available source programs. Includes preserve path spelling and create fresh program objects. Missing-file failures use `ProcessingException`; repeated include paths remain errors. The engine does not open files, scan directories, or fetch source. Macro definition/expansion belongs to [macros](../macros/README.md) and the assembler passes, not a second expansion engine inside tokenization.

## Classification and character data

Token classification keeps macro-parameter, register, integer, floating, operator, directive, string, and identifier rules in their original precedence. `Binary.isIntegerCandidate()` avoids guaranteed numeric failures for ordinary names, while every accepted candidate still goes through full parsing. Floating classification reproduces Java parse-success grammar and whitespace boundaries; directive data conversion occurs later.

`JavaCharacter` uses [character-data.json](character-data.json) so browser Unicode versions cannot change the JDK 21 classifications consumed by assembly and highlighting. The [highlighting capture runner](../../../../../tests/oracle/highlighting/run.mjs) generates/checks both its oracle table and this engine copy. Relocation does not change the generated bytes or expected categories.

[Tokenizer comparisons](../../../../../tests/oracle/tokenizer-units/README.md) cover full sources, includes, equivalences, diagnostics, and every BMP code unit's letter/digit categories. [Assembler units](../../../../../tests/oracle/assembler-units/README.md) cover records, clones, metadata, and lexical precedence. These are source-analysis contracts, not instruction-execution evidence.
