# Memory dump encoders

This module owns the six enabled legacy memory-dump formats and populated GUI segment discovery. It translates `AbstractDumpFormat`, `AsciiTextDumpFormat`, `BinaryDumpFormat`, `BinaryTextDumpFormat`, `HexTextDumpFormat`, `IntelHexDumpFormat`, `SegmentWindowDumpFormat`, and `DumpFormatLoader` from [mars/mips/dump](../../../../_legacy-app/mars/mips/dump/), plus [MemoryDump](../../../../_legacy-app/mars/util/MemoryDump.java) and range selection from [FileDumpMemoryAction](../../../../_legacy-app/mars/venus/FileDumpMemoryAction.java). The legacy MIF class is deliberately disabled and is not registered here.

Every encoder is bound to one [Globals](../Globals.ts) instance. Addresses and raw words use signed 32-bit `number` patterns, with unsigned shifts for byte extraction. `dumpMemoryRange` takes inclusive aligned word bounds and returns caller-owned UTF-8/LF text bytes or raw binary bytes; it stops at the first unallocated word and propagates memory errors. Shared [numeric formatting](../formatting/README.md) supplies unsigned address display and minimum-width radix padding; format-specific widths, prefixes, and Intel HEX uppercasing stay with the encoders. There is no file I/O, browser dependency, mutable registry cache, subscription, or teardown. Java classpath discovery becomes explicit construction in the same discovery order. `MemoryDump` is placed here rather than hardware utilities because its only responsibility is selection of dump ranges.

The GUI offers populated `.text` and `.data` ranges using the current configuration. Text stops at the first missing instruction; data includes allocated zero words through the end of the first contiguous run of allocated 4 KiB blocks. It does not jump across an unallocated gap, include `.ktext`, or include static data below `dataBaseAddress`. Reset, execution, and debugger writes are reflected by the next dump.

Binary emits each raw word least-significant byte first even with big-endian memory. Hexadecimal text uses lowercase eight-digit words, binary text uses 32 digits, and ASCII uses the existing three-column Java character renderer. Intel HEX preserves the legacy relative offsets, word-byte order, checksums, uppercase output, and EOF record; it deliberately does not repair the legacy handling of offsets above 16 bits. Segment Window reads the machine's address/value preferences, source metadata, and basic assembly; data rows contain eight words and a final partial row is discarded, matching Java.

The [oracle fixture](../../../../tests/oracle/dump-units/README.md) and [consumer](dump.test.ts) compare all six encodings across the three layouts, display bases, byte orders, sparse stops, partial rows, reversed ranges, and alignment errors. Offsets above 16 bits are source-translated but not covered by that fixture. Browser filename extensions and deterministic LF/UTF-8 text are host adaptations under [ADR 0003](../../../../docs/adrs/0003-browser-file-workflows.md) and [UI-P0008](../../../../docs/deviations.md#ui-p0008-memory-dump-files).
