# MIPS engine

The engine owns framework-free, session-local MIPS behavior. Hardware, memory, tokenization, assembly, instruction execution, numeric conversions, and diagnostics retain the canonical Java class responsibilities. The browser supplies presentation and host services; the engine never imports Svelte, the DOM, or platform I/O. `Globals` composes an independent machine, and `MIPSprogram` carries its source, assembly results, and undo history. The [Venus controller](../venus/RunController.ts) coordinates desktop workflows over these classes.

Java static machine state becomes instances owned by a session. Registers and memory publish synchronous access notices with caller-owned unsubscribe functions. Host callbacks receive backstep records and identify access origin; the current program owns whether recording is enabled. Debugging output is an injected writer. Immutable instruction and directive metadata may be shared, but register bits, configuration selection, and memory belong to their session. Simulation yields through an injected scheduler and awaits input services; its owner must stop and await it before resetting or releasing the machine ([ADR 0004](../../../docs/adrs/0004-cooperative-simulation.md)).

Signed words use normalized 32-bit `number` values; 64-bit bit patterns use signed `bigint`. Hardware floating-point registers retain raw integer bits. Engine modules name their Java sources and retain MARS copyright and MIT attribution. The [oracle directory](../../../tests/oracle/README.md) owns unit and whole-program captures; assembly, instruction callbacks, memory, floating conversions, deterministic console syscalls, simulator sequencing, and undo have direct Java comparisons. Passing these comparisons does not establish unimplemented platform syscall or tool behavior. Those families remain explicitly deferred; the web application has no command-line launcher or program-argument adapter.
