# Numeric and character compatibility

This module owns binary, hexadecimal, decimal, and ASCII-display conversions and Java runtime character/numeric compatibility used by the engine and views. `Binary` directly translates `_legacy-app/mars/util/Binary.java`; its ASCII display uses `Config.properties` and `_legacy-app/mars/Globals.java` padding behavior. It also shares the unsigned address-display rule consumed from `mars/venus/NumberDisplayBaseChooser.java` by assembly diagnostics and Segment Window dumps, and minimum-width unsigned radix padding used by the text dump formats. Prefixes, uppercasing, and format-specific widths remain with their callers. This module has no machine state or platform dependencies.

The shared 16-bit sign-extension primitive preserves the same masked-shift behavior in statement decoding, pseudo expansion, and instruction execution.

Words are signed 32-bit `number` values. Long values are signed 64-bit `bigint` values. Bit shifts retain Java's masked distances; integer parsing reproduces `Integer.decode`/`Long.decode` syntax and MARS's additional two's-complement and decimal fallback paths. The fallback intentionally accepts empty input as zero, accepts decimal overflow with 32-bit wrap, and classifies negative hexadecimal as octal in the same cases as the legacy source. These quirks are preserved rather than silently corrected.

`Binary.isIntegerCandidate` checks only whether the first UTF-16 code unit can begin a supported integer. It recognizes the same JDK decimal digits as the parser, optional signs, hexadecimal `#`, and the empty-string fallback. Register lookup and token classification use it to skip guaranteed parsing failures for ordinary names without allocating caught exception stacks. A positive result still requires the unchanged full parser; it does not establish that a string is a valid integer.

The [foundation probe](../../../../tests/oracle/units/README.md) records conversion boundaries, parsing failures, legacy classification quirks, bit/byte operations, ASCII padding, 64-bit composition, and every BMP digit accepted by JDK 21 hexadecimal integer parsing. Raw FPU bit conversion belongs to hardware.

`JavaCharacter` adapts consumed JDK operations on UTF-16 code units using [character-data.json](character-data.json), generated from the pinned JDK 21 by the [highlighting probe](../../../../tests/oracle/highlighting/README.md). Decimal digit values, letter/digit categories, and Java `String.trim` semantics are shared by integer parsing, tokenization, diagnostics, console input, and editor highlighting. Trimming removes only code units at or below U+0020; it does not use JavaScript's Unicode-whitespace trimming. This adapter and its generated table live here so foundational parsing and formatting do not depend on the assembler. Supplementary characters remain pairs of Java `char` values, and generated categories are independent of the browser's Unicode version.

`JavaFloatingPoint` supplies the Java runtime conversions consumed by MARS: single/double printing, parsing, saturating floating-to-int narrowing, and canonical float-bit conversion. It independently implements the [Java SE 21 Double decimal-selection specification](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html#toString%28double%29) and [Float parsing contract](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Float.html#parseFloat%28java.lang.String%29) with exact `bigint` fractions and nearest-even rounding. Printing selects the shortest round-tripping decimal, including Java’s one-or-two-digit rule, then applies Java notation thresholds. Parsing accepts Java decimal/hexadecimal syntax and whitespace, preserves signed zero, and rounds directly to the requested binary precision. Token classification uses the same literal grammar through a predicate that neither constructs parsed fractions nor allocates exception or match arrays. In particular, parsing a float through an intermediate JavaScript double can round twice and is not used here. Narrowing shares Java's NaN-to-zero, saturation, and truncation rules between assembler alignment and instruction execution; instruction-specific rounding and validation remain with their original algorithms. Canonical `Float.floatToIntBits` conversion accepts caller-owned scratch views and canonicalizes NaN; raw NaN-preserving hardware writes remain distinct. No OpenJDK implementation or lookup tables are copied.

The [floating conversion oracle](../../../../tests/oracle/floating-units/README.md) compares JDK 21 public APIs over every exponent, boundary significands, signed special values, seeded bit patterns, exact rounding midpoints, extreme exponents, and invalid syntax. This module adapts Java runtime semantics; it does not replace any MARS assembler or simulator algorithm.
