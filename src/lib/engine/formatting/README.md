# Numeric representation

This module owns binary, hexadecimal, decimal, and ASCII-display conversions used by the engine and views. `Binary` directly translates `_legacy-app/mars/util/Binary.java`; its ASCII display uses `Config.properties` and `_legacy-app/mars/Globals.java` padding behavior. It has no machine state or platform dependencies.

Words are signed 32-bit `number` values. Long values are signed 64-bit `bigint` values. Bit shifts retain Java's masked distances; integer parsing reproduces `Integer.decode`/`Long.decode` syntax and MARS's additional two's-complement and decimal fallback paths. The fallback intentionally accepts empty input as zero, accepts decimal overflow with 32-bit wrap, and classifies negative hexadecimal as octal in the same cases as the legacy source. These quirks are preserved rather than silently corrected.

`Binary.isIntegerCandidate` checks only whether the first UTF-16 code unit can begin a supported integer. It recognizes the same JDK decimal digits as the parser, optional signs, hexadecimal `#`, and the empty-string fallback. Register lookup and token classification use it to skip guaranteed parsing failures for ordinary names without allocating caught exception stacks. A positive result still requires the unchanged full parser; it does not establish that a string is a valid integer.

The [foundation probe](../../../../tests/oracle/units/README.md) records conversion boundaries, parsing failures, legacy classification quirks, bit/byte operations, ASCII padding, 64-bit composition, and every BMP digit accepted by JDK 21 hexadecimal integer parsing. Raw FPU bit conversion belongs to hardware.

`JavaFloatingPoint` supplies the Java runtime text conversions consumed by MARS: single/double printing and parsing. It independently implements the [Java SE 21 Double decimal-selection specification](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html#toString%28double%29) and [Float parsing contract](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Float.html#parseFloat%28java.lang.String%29) with exact `bigint` fractions and nearest-even rounding. Printing selects the shortest round-tripping decimal, including Java’s one-or-two-digit rule, then applies Java notation thresholds. Parsing accepts Java decimal/hexadecimal syntax and whitespace, preserves signed zero, and rounds directly to the requested binary precision. In particular, parsing a float through an intermediate JavaScript double can round twice and is not used here. No OpenJDK implementation or lookup tables are copied.

The [floating conversion oracle](../../../../tests/oracle/floating-units/README.md) compares JDK 21 public APIs over every exponent, boundary significands, signed special values, seeded bit patterns, exact rounding midpoints, extreme exponents, and invalid syntax. This module adapts Java runtime semantics; it does not replace any MARS assembler or simulator algorithm.
