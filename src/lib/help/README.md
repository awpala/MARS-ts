# Help articles

This module owns the Help menu catalog, the tabbed Help browser, and article presentation: the existing F1 overview and About MARS content, plus eleven articles adapted from the original MARS help. Help and About MARS remain the first two menu entries, followed by a thin divider separating the added article entries. Venus owns the selected article and opens it using the application’s shared [Modal](../venus/components/dialogs/Modal.svelte). The Help command (F1, toolbar, or the Help menu's first entry) opens the [HelpBrowser](HelpBrowser.svelte) instead of a single article. Its catalog-defined tabs are Overview, MIPS, MARS, Bugs/Comments, and Acknowledgements; MIPS nests Syscalls, Exception Handlers, and Macros, while MARS nests Introduction, Debugging, Settings, Tools, Limitations, and Release History. The first opening after page load shows the overview. Venus retains the selected top-level tab and each tab's nested article, so reopening Help returns to the last view. Desktop session recovery ([ADR 0007](../../../docs/adrs/0007-desktop-session-recovery.md)) keeps that selection across reloads and reopens the browser, once the desktop is revealed, if it was open immediately before the reload; single menu articles start closed. Tab strips and the Close action stay fixed while the selected article scrolls in a keyboard-focusable region. Switching tabs remounts the article, so it reopens at the top. Individual Help-menu entries still open one article without tabs and do not change the browser's retained selection. The generic dialog remains outside this module; it owns focus containment, initial focus, dismissal, scrolling, and focus restoration. Help owns no editor, simulator, or browser-storage state. Each embedded code block has a Copy icon and an Open as new file icon. Both controls use the shared [Clipboard component](../venus/components/transfers/Clipboard.svelte), with copy-code and transfer-to-file variants. Copy uses the Clipboard API with inline success/failure feedback; opening delegates the exact displayed code text to Venus’s normal new-file/edit workflow, preserves existing buffers, closes Help, and respects Auto Save. Opening code is disabled during execution. Article attachments mount these Svelte controls beside each intact HTML code block once per displayed article and unmount them when the article is replaced or closed; late clipboard completions cannot update a disposed control. The open permission reaches the mounted control as a reactive prop, so a run starting, pausing, or stopping while Help is open enables or disables Open without replacing the controls, their keyboard focus, or their Copy feedback.

The catalog keeps menu metadata in the initial bundle and dynamically imports each reviewed HTML fragment only when its article opens. Vite emits these fragments as separate hashed JavaScript assets; the F1 overview and About content remain immediately available. The dialog shows loading status or a load-failure message while preserving dismissal and focus behavior. Closing or switching articles discards the previous view, so a late import cannot replace the current article. The article component renders only these trusted, repository-authored module strings; never pass editor text, imported files, arbitrary network responses, or other user content to its raw-HTML path. Articles use scoped descendant styling for readable headings, lists, code, and tables in both themes. The syscall service reference has a keyboard-focusable scroll region capped at 420 px or 55% of the viewport height, with sticky column headers and alternating row bands in both themes. Its fixed column proportions allocate 20% to Service, 12% to Code, 26% to Arguments, 26% to Result, and 16% to MARS-ts; narrow viewports can scroll horizontally. External reference and license links open a separate tab while the article remains open. The article footer's attribution link to the original online MARS help and the bundled-license links in article footers and About use the shared [LinkedResource control](../venus/components/controls/LinkedResource.svelte); reference links inside the reviewed fragments carry the same new-tab attributes in their HTML. There is no runtime dependency on the legacy tree or a remote documentation site: article content is bundled, and the online MARS help is only an outbound link.

## Legacy sources and attribution

Adapted from MARS, copyright 2003–2013 Pete Sanderson and Kenneth Vollmar, under the [MIT license](../../../MARSlicense.txt). Each derived fragment retains its own source and copyright header; articles display attribution, an outbound link to the original MARS help, and a link to the bundled license. Contributor names, original article dates, historical release dates, bibliography dates, and example credits are retained. The original Java files and help pages remain unchanged.

The original [HelpHelpAction.java](../../../_legacy-app/mars/venus/HelpHelpAction.java) organized these documents into Swing tabs: MIPS (operand key, Basic Instructions, Extended Instructions, Directives, Syscalls, Exceptions, Macros), MARS (Intro, IDE, Debugging, Settings, Tools, Command, Limits, History), License, Bugs/Comments, Acknowledgements, and Instruction Set Song. The browser retains that order and nesting for the bundled articles, prefixes an Overview tab holding the existing introductory text, and reuses the Help-menu captions. The operand key, generated instruction/directive lists, IDE, Command, License, and Instruction Set Song tabs are not part of this content; the license remains linked from article footers and About. Each article is also a Help dropdown entry with a same-tab dialog. Existing browser overview and About content were moved from Venus into this module; the [About action](../../../_legacy-app/mars/venus/HelpAboutAction.java) is the legacy counterpart of the latter.

## Maintenance and validation

Update current-use articles when their corresponding implemented workflows change. Preserve historical records and explicit legacy examples; do not silently rewrite Java release history into TypeScript history. Keep availability notes consistent with the [syscall registry](../engine/syscalls/README.md), [Venus workflows](../venus/README.md), and [implementation guide](../../../IMPLEMENTATION.md). Consequential behavior adaptations remain governed by [ADR 0002](../../../docs/adrs/0002-port-fidelity.md), [browser files](../../../docs/adrs/0003-browser-file-workflows.md), and [cooperative execution](../../../docs/adrs/0004-cooperative-simulation.md).

The [browser scenarios](../../../tests/browser/help.spec.ts) exercise the tabbed browser's overview opening, tab order and nesting, Bugs/Comments links, selection retained across openings, browser and selection recovery across reload (with closed and single-article Help staying closed), fixed tab strips and Close action, standalone menu articles, on-demand article loading, failed and late imports, every menu article, retained attribution and dates, syscall availability, long-article and sticky-table scrolling, exact snippet copying, clipboard failure feedback, new editor sources, keyboard dismissal/focus restoration, and the existing overview access path. The [lifetime scenarios](../../../tests/browser/lifetime.spec.ts) keep a code control's identity, focus, and Copy feedback while execution stops behind an open article. The [desktop scenarios](../../../tests/browser/desktop.spec.ts) cover About MARS and its license link, Settings menu ordering and separators, and shared menu/toolbar toggle state before and after reload. [Catalog tests](articles.test.ts) pin the tab order, and that every menu article except About appears exactly once. App gates validate the component/catalog integration. This content addition changes no engine algorithms and makes no new oracle-parity claim.
