# MIPS editor highlighting

This module translates the lexical highlighting behavior of `_legacy-app/mars/venus/editors/jeditsyntax/tokenmarker/MIPSTokenMarker.java`, its Token and TokenMarker collaborators, KeywordMap, and the default styles from SyntaxUtilities. It paints source text; it does not assemble instructions, validate programs, or supply substitute simulator logic.

The scanner preserves the Java state machine, including alternating escape state, keyword boundaries, percent-prefixed macro parameters, the label heuristic (including instruction names used as labels), completed character literals receiving the string-literal token ID, and incomplete literals becoming INVALID at the end of their line. All offsets and token lengths use UTF-16 code units. Label validity comes from the engine's TokenTypes and character categories from its JDK-generated JavaCharacter helper. KeywordMap preserves Java's bucket lookup, newest-entry precedence, case sensitivity, and one-character uppercase conversion.

TokenMarker owns each document's line states and reuses linked-list nodes, including its END sentinel. Consumers must copy painting results before another line is marked. `highlightSource` returns detached source spans, retaining every code unit and newline; it creates a fresh marker for each snapshot so files cannot share lexical state. Java's backing-array capacity management becomes ordinary TypeScript arrays; logical line counts and insertion/deletion responsibilities remain intact.

The [Java probe](../../../../tests/oracle/highlighting/README.md) generates the complete basic/pseudo instruction mnemonic vocabulary, JDK uppercase metadata, and default colors/font styles. Existing engine directive and register APIs supply the remaining keyword identities. This includes every mnemonic in the checked-in Java implementation and does not claim that corresponding assembler or execution behavior is implemented. Source data is read-only and never fetched remotely. Generated JSON may be reformatted; the checker compares parsed metadata exactly and the full oracle capture byte-for-byte.

The Venus presenter uses escaped Svelte text spans in an `aria-hidden` preformatted overlay. The native textarea remains the sole accessible editable surface and owns caret, selection, scrolling, clipboard events, and undo integration. Both surfaces use identical monospace metrics, tab stops, padding, and line height; horizontal and vertical scroll offsets translate the paint layer. Forced-colors mode falls back to native visible textarea text. The terminal newline added only to the paint surface gives an empty final line measurable height and does not alter saved source. The generic editor and source/messages layout remain separate responsibilities.

The exact/prefix instruction-help methods of MIPSTokenMarker are completion/help responsibilities and are not implemented by this lexical module; the desktop's instruction hover help reads the engine's instruction metadata instead. Syntax-style preferences are deliberately replaced by bundled presets, and live instruction popup completion remains outstanding. The golden tests establish lexical token parity for their captured corpus, not complete desktop GUI parity.
