# Core syscall oracle

`CoreSyscallProbe.java` runs the canonical service classes through the original `SyscallLoader`, against real MARS registers and memory, with isolated `SystemIO` input and captured output. Reflection replaces only the private cached input reader so each case gets a fresh deterministic string; no legacy sources are changed. The [shared probe runner](../units/run.mjs) owns the temporary Java class directory, fresh preferences, JDK/source integrity checks, exact streams/status, and source hashes.

Run `node tests/oracle/core-syscalls/run.mjs --update` to regenerate and `node tests/oracle/core-syscalls/run.mjs --check` to verify, after `build-legacy` has produced a current jar. Do not edit golden results by hand.

The 192 rows cover 16 services, each with 12 cases: integer/float/double/string/character console I/O, heap allocation, normal exit, and hexadecimal/binary/unsigned integer printing. Inputs include signed boundaries, overflow, empty input, Java Unicode digits, hexadecimal floating syntax, NaN/infinity, UTF-16 text, and a single-precision double-rounding boundary. Output cases include signed zero, NaN, infinities, subnormals, maximum finite floating values, NUL-terminated byte strings, and invalid memory. Every row records raw output, exact runtime diagnostics or normal exit, relevant general/FPU/CP0 registers, and the entire affected string buffer. Heap allocation cases intentionally retain the allocator's evolving address, including canonical overflow behavior.

The oracle runs headlessly to capture deterministic results. The TypeScript application keeps the corresponding GUI behavior: `Exit2` terminates without exposing a process exit code, and input/output is supplied by an injected browser adapter. The probe compares normal-exit signaling, not command-line process integration. Popup prompts and console newline handling are checked separately against the GUI branches read from `SystemIO.java` and `MessagesPane.java`; no Swing visual-test claim is made.
