# Random, dialog, and MIDI syscall oracle

`PlatformSyscallProbe.java` invokes the actual legacy `SyscallLoader` services 40–44 and 50–59, and `MidiSyscallProbe.java` invokes services 31 and 33, without changing Java source. The shared [probe runner](../units/run.mjs) compiles against the immutable jar, isolates Java Preferences, records source hashes and exact stdout/stderr/status, and verifies the pinned JDK. Run `build-legacy`, then `node tests/oracle/platform-syscalls/run.mjs --update` to regenerate all three captures or `--check` to verify them. Never edit expected results by hand.

`random.json` runs headlessly. It covers signed seed and stream-ID boundaries, mixed integer/float/double draws, powers of two and rejection-heavy bounds, zero/negative errors, revisiting independent streams, and reseeding an existing stream. The preexisting [seeded whole program](../programs/random.asm) is enabled in the production-engine corpus comparison too. Unseeded startup entropy is tested through an injected host, not compared with nondeterministic Java values.

`dialogs.json` runs actual `JOptionPane` operations under `xvfb-run -a` with headless mode disabled. A Swing timer finds the active pane, captures its message/type, and supplies deterministic input, confirmation options, or window-close results. It never replaces a syscall algorithm. The probe disposes its windows and the runner removes the display/preferences/class-directory resources. Xvfb, xauth, AWT X11 libraries, fontconfig, and DejaVu fonts are required and provisioned with CI; ordinary CLI and existing method probes stay headless.

Dialog cases cover Yes/No/Cancel/close, numeric null/empty/invalid/boundary/Unicode/whitespace/hexadecimal/NaN/infinity/signed-zero inputs, string truncation and tiny/negative/overflowing bounds, UTF-16 low-byte writes, invalid prompt/destination/suffix addresses, partial memory writes, numeric message formatting, byte-to-char messages, and message-type normalization. Every TSV row contains service/case, original argument/FPU words, response, diagnostic outcome, captured message/type, and final general/FPU/CP0 registers plus the affected buffer bytes. The [Vitest comparison](../../../src/lib/engine/syscalls/platform-syscalls.test.ts) runs rows in capture order to preserve stream state.

`midi.json` runs headlessly. Its first row calls MidiOutSync before any probe device exists: on a host without an audio output line, as in the dev container and CI, Java reports `MidiUnavailableException: Can not open line` and the service returns before its duration. The probe captures only that exception's first line, so JDK stack-frame line numbers do not enter the golden. It then writes a `javax.sound.midi.spi.MidiDeviceProvider` service file into its own temporary class directory and selects the provider through the `javax.sound.midi.Sequencer` and `javax.sound.midi.Receiver` system properties. The provider's sequencer is a proxy around a new JDK real-time sequencer for each tone, so the legacy code opens, configures, starts, and closes a real sequencer whose timing and end-of-track event are genuine; the receiver port accepts every message. The proxy records the legacy call order, the exact requested `Sequence` (division, resolution, and every event's tick and bytes), and the messages dispatched up to the first note-off; the JDK sequencer's later controller resets vary with timing and are not Tone's messages. Rows are tab-separated: service, row number, `$a0`–`$a3` (comma-separated for a paired call), outcome, the final `$v0` and `$a0`–`$a3`, and one observation per tone of `calls;sequence;received;endedBeforeReturn;spanOk`. Timing enters only as deterministic values: `endedBeforeReturn` records whether the tone had closed before `simulate` returned, and `spanOk` records whether the dispatched note-off followed the note-on within the duration minus 5 ms to plus 250 ms (`-` when the probe does not await the note-off). Cases cover in-range boundaries, each out-of-range default, values with high bits set, `Integer.MIN_VALUE` and `MAX_VALUE` arguments, zero and negative durations, asynchronous tones, two overlapping asynchronous tones reported in request order with an `overlapped` flag, and a maximal duration observed through its note-on. The probe exits explicitly because ToneGenerator's pool threads are non-daemon and the maximal tone never ends.

The [Vitest comparison](../../../src/lib/engine/syscalls/platform-syscalls.test.ts) decodes each sequence, requires resolution 1 and tempo 1000 microseconds per tick so ticks are milliseconds, and compares the program change, note-on pitch and velocity, and note-off tick with the tone the port hands its host. Synchronous rows must suspend until the host ends the tone; asynchronous rows must return without waiting; register state must match. The no-device row runs against a machine without a tone host, which returns at once. These captures establish service arguments, defaults, and wait semantics, not audio output, timbre, or Java's sequencer latency; [ADR 0015](../../../docs/adrs/0015-midi-web-audio-tones.md) records the browser's sine-tone adaptation.

The captures establish service effects, not Swing pixel/focus parity. The [browser tests](../../browser/execution/syscalls.spec.ts) separately establish same-tab presentation, Cancel versus Stop, initial focus, no echo, and the existing handler-dispatch integration. [ADR 0014](../../../docs/adrs/0014-random-and-dialog-syscalls.md) records browser adaptations and checkpoint/entropy ownership.
