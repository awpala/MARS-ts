# Automatic exception-handler workflow oracle

This probe calls the unchanged private `RunAssembleAction.buildFileNameList` and `SettingsExceptionHandlerAction.performOK` through reflection, without constructing a Swing window. It captures filename wrapping at and beyond 60 counted characters, separator and trailing-newline behavior, duplicate source names, checkbox/name changes, and notification counts. The missing-file observation records Java's diagnostic text; the browser deliberately uses its virtual-library diagnostic instead. A real two-source assembly executes a trap, enters kernel text, advances EPC, and returns through `eret` before normal completion.

Run `build-legacy`, then `node tests/oracle/exception-handler/run.mjs --update` to regenerate, or `--check` to compare fresh oracle output. Only the capture runner writes expected results; the Java sources remain read-only. [Session tests](../../session/exception-handler.test.ts) compare the formatter, compatible legacy toggle/commit behavior, and execution state. [Browser settings scenarios](../../browser/settings/settings.spec.ts) exercise the dialog and its deliberate independent-selection workflow: filenames are now saved even while disabled, as documented in [ADR 0013](../../../docs/adrs/0013-exception-handler-workflow.md). The capture does not prove Swing window interaction; dialog labels, enabled state, and browse rules are source comparisons with `mars/venus/SettingsExceptionHandlerAction.java`.
