# Runtime program arguments oracle

This boundary captures the unchanged `mars/simulator/ProgramArgumentList.java` implementation. `ProgramArgumentsProbe.java` records JSON-lines observations of the GUI string constructor: empty input, the five StringTokenizer delimiters, literal quotes, non-delimiter whitespace, UTF-16 byte truncation, the default stack gap at and beyond its boundary, and both compact layouts. Each observation contains the base64-encoded input, configured memory layout, `$sp`/`$a0`/`$a1`, argc/argv/null stack words, and complete stored string bytes. Seeded register values verify that empty input does not overwrite registers and that nonempty input uses the configured initial stack rather than a manually changed `$sp`.

`ProgramArgumentsFailureProbe.java` captures the diagnostic and process exit when argument bytes exceed a compact address space. The port raises the same diagnostic to its owner instead of terminating the browser, as specified in [ADR 0009](../../../docs/adrs/0009-program-arguments.md).

After `build-legacy`, run `node tests/oracle/program-arguments-units/run.mjs --update` to regenerate the two captures or `--check` to verify them. The shared method-probe runner isolates Java preferences and records command, input, streams, exit status, and source hashes. Expected data is generated only by the oracle. [The session comparison](../../session/program-arguments.test.ts) checks the translated storage algorithm and first-Go/Step lifecycle; the original corpus separately exercises program output. The legacy sources remain read-only, with Pete Sanderson and Kenneth Vollmar's MIT attribution retained in the port.
