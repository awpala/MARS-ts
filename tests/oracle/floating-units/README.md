# Java floating runtime oracle

`FloatingProbe.java` records JDK 21 `Float.toString`, `Double.toString`, `Float.parseFloat`, and `Double.parseDouble`. Run `node tests/oracle/floating-units/run.mjs` to capture or append `--check` for byte-identical comparison. The shared [probe runner](../units/README.md) pins JDK 21 and captures command, input, stdout, stderr, status, and source provenance.

The fixture contains 7,168 binary32 formatting cases, 16,384 binary64 formatting cases, and 3,162 input strings parsed into both precisions. Formatting covers every encoded exponent with boundary significands and both signs, then 4,096 seeded raw patterns for each precision. Parsing includes round-trip decimal and hexadecimal strings, exact midpoint values and neighbors around normal/subnormal transitions, decimal powers from `1e-325` through `1e310`, hexadecimal exponent boundaries, Java whitespace/suffix rules, signed zeros, infinities, NaNs, malformed input, and overflow/underflow. Float input `1.0000000596046447753906250001` distinguishes direct single-precision rounding from incorrectly parsing a double first. This is broad deterministic coverage, not an exhaustive enumeration of all bit patterns or input strings.

`JavaFloatingPoint.ts` is an independent implementation of the published [Java SE 21 Double decimal-selection specification](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html#toString(double)) and [Float parsing specification](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Float.html#parseFloat(java.lang.String)). It uses exact integer fractions to compare decimal candidates against binary rounding intervals and performs one nearest-even rounding when parsing. The installed JDK public documentation and actual API results establish the behavior. No OpenJDK implementation or precomputed tables are copied, and this adapter remains under the repository’s MIT license.

Fixture rows use `F`/`D` plus unsigned hexadecimal raw bits and the exact printed string; `P` rows use a base64-encoded source string followed by canonical float and double result bits, or `error` for rejected syntax. Tests compare canonical NaN bits because the Java parse APIs return canonical NaN; formatting tests include noncanonical NaN inputs. Native Java exception text is not reproduced by this helper: invalid input uses the existing engine `NumberFormatException`, which consuming MARS classes translate into their own diagnostics.
