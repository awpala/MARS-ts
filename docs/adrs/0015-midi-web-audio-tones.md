# ADR 0015: MIDI syscalls as Web Audio sine tones

- **Status**: Accepted
- **Date**: 2026-10-30

## Context

Services 31 (MidiOut) and 33 (MidiOutSync) are the only audio in the legacy application; no Tool produces sound. [SyscallMidiOut](../../_legacy-app/mars/mips/instructions/syscalls/SyscallMidiOut.java) and [SyscallMidiOutSync](../../_legacy-app/mars/mips/instructions/syscalls/SyscallMidiOutSync.java) read `$a0`–`$a3`, replace an out-of-range pitch, instrument, or volume (0–127) and a negative duration with 60, 0, 100, and 1000, and write no registers. [ToneGenerator](../../_legacy-app/mars/mips/instructions/syscalls/ToneGenerator.java) then opens a new `javax.sound.midi` sequencer per tone and plays a one-track sequence: a program change and note-on at tick 0 and a note-off at tick `duration` on channel 0, with a resolution of 1 tick per quarter and a tempo of 1000 microseconds per quarter, so one tick is one millisecond. Service 31 plays it on a cached thread pool and returns immediately. Service 33 plays it on the simulator thread and waits for the end-of-track event. `Simulator.stopExecution` only sets a flag, so Stop or Pause during a service 33 tone takes effect after the tone ends. Nothing silences a tone that has started. Without a sound line, Java prints a `MidiUnavailableException` stack trace to its own stderr and the service returns at once. The JDK's default synthesizer provider creates a new synthesizer for each tone, so tones never share channel state, and the legacy Help states that the instrument's sound depends on the synthesizer.

Web Audio has no General MIDI synthesizer. Web MIDI, the literal passthrough, is unavailable in Safari, requires a permission prompt elsewhere, and sounds only when the operating system provides a synthesizer. The browser therefore has to synthesize the tone itself. The human requested a minimum-viable sound engine for 1.0: simple sine waves rather than instrument emulation. Browsers also start audio only after user interaction, and the engine must stay free of audio and timer APIs.

## Decision

### Engine

Port `ToneGenerator`, `SyscallMidiOut`, and `SyscallMidiOutSync` in the [MIDI syscall family](../../src/lib/engine/syscalls/README.md) with their canonical names, numbers, defaults, and validation order. `AbstractMidiSyscall` holds the argument validation duplicated in the two Java classes. Each machine owns one `ToneGenerator`, which hands the validated `Tone` (pitch, duration, instrument, volume) to an optional injected `ToneGeneratorHost` in place of the sequencer and its end-of-track listener. Service 31 ignores the host's completion. Service 33 returns the host's promise, so the simulator suspends the current instruction as it does for input ([ADR 0004](0004-cooperative-simulation.md)). A machine without a host plays nothing and service 33 returns without waiting, as Java does without a MIDI device; no stack trace is reproduced. Host failures are swallowed as Java's tone code swallows its MIDI exceptions.

### Browser sound

[WebAudioToneHost](../../src/lib/browser/WebAudioToneHost.ts) plays every tone as one sine oscillator at the equal-tempered frequency 440 · 2^((pitch − 69) / 12). The instrument number has no audible effect. Gain peaks at 0.2 · (volume / 127)², the square law of the General MIDI velocity curve, with a 5 ms fade-in and a 30 ms fade-out after the duration to avoid clicks. Volume 0 and duration 0 create no voice. At most 32 voices sound together; another tone fades out the oldest. Go and Step call `prepare()` synchronously within their user gesture, which creates or resumes the audio context there so autoplay policy permits sound. The context is suspended after two seconds without a sounding voice and resumed for the next tone. Each desktop machine owns its host, and teardown silences every voice and closes the context.

### Timing and Stop

The browser host resolves a tone's wait with a timer at its duration, independent of the audio graph. Service 33 therefore waits the full duration even when the browser blocks or lacks audio, so program timing does not depend on whether sound is audible. This differs from Java's no-device path, which returns at once. The engine's stop listener releases every pending tone wait through the same host release that ends pending input and dialogs, so Stop and Pause apply at the syscall boundary immediately rather than after the tone. A tone requested after a stop request still sounds but does not suspend the stopping run. Tones that have started continue to their scheduled end after Stop, Pause, or Reset, as in Java. Tone waits are never serialized in recovery checkpoints, and Backstep does not undo sound, just as it does not undo console output.

## Evidence and consequences

The [MIDI method probe](../../tests/oracle/platform-syscalls/README.md) runs the actual legacy services against a recording output device: a wrapper around the JDK's real-time sequencer records the requested sequence, tempo, dispatched messages, and end-of-track ordering. The capture covers in-range boundaries, every default, values with high bits set, `Integer.MIN_VALUE` and `MAX_VALUE`, zero duration, overlapping asynchronous tones, a maximal duration, and the headless no-device path. [Engine comparisons](../../src/lib/engine/syscalls/platform-syscalls.test.ts) check every captured tone, default, register state, and synchronous/asynchronous return against the port, plus host-failure handling and suspension and Stop release through the actual syscall instruction. [Host tests](../../src/lib/browser/WebAudioToneHost.test.ts) cover frequency, gain, envelope, timing, release, the voice limit, context lifetime, and missing Web Audio. [Browser scenarios](../../tests/browser/syscalls.spec.ts) play real Chromium oscillators from the Go gesture and release a pending tone with Stop.

These comparisons establish service arguments, defaults, wait semantics, and machine state. They do not establish timbre parity, which the legacy Help disclaims and the sine engine does not attempt, or Java's sequencer startup latency. Autoplay behavior is automated in Chromium only; Safari and Firefox need manual confirmation. A richer synthesizer could later replace the host without changing the engine contract. [UI-P0009 and ENG-P0005](../deviations.md) record the adaptations.
