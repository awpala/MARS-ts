# ADR 0013: Automatic exception-handler selection in the browser

- **Status**: Accepted
- **Date**: 2026-10-29

## Context

The engine already prepares an enabled exception handler before the lead source and dispatches exceptions to kernel text. The legacy [settings action](../../_legacy-app/mars/venus/SettingsExceptionHandlerAction.java) supplies a modal checkbox and read-only pathname with Browse, OK, and Cancel. The browser needs this workflow over its existing virtual source library rather than Java's filesystem chooser.

## Decision

Use an initially off **Enable exception handler** switch. While off, both handler radio choices are disabled and dimmed, and the selected identity remains intact. Browse and the plain-text filename appear only for the custom choice; Browse is disabled while inclusion is off. Selecting SPIM hides that entire custom-file row. OK persists the enabled flag and selected filename independently, including a filename chosen while enabled and then disabled before OK; both survive reopening and application reload. Cancel, close, and Escape discard drafts. Unlike legacy `performOK`, disabling does not discard a newly chosen filename. The command remains available during execution; changes affect future assemblies without invalidating, resetting, or interrupting loaded code. The default-source preview remains available while inclusion is off because viewing it does not change settings.

Browse lists saved library entries only, sorted like Open, and preselects the current draft handler when it still exists. Never-saved buffers are excluded so the selected identity can survive reload. When a saved handler has an open buffer, assembly uses current working text, consistent with lead-file and `.include` resolution. This deliberately differs from Java reading the saved handler file. No `.ktext` validation is added, and duplicate handler inclusion retains the assembler's existing errors.

Bundle the supplied SPIM default handler and startup code unchanged under [static/sources](../../static/sources/README.md), preserving James R. Larus’s BSD notice. A separate **Use SPIM default exceptions handler** radio selects its reserved `/SPIM:/exceptions.s` identity, whose colon-bearing namespace cannot collide with a user-library name or root-relative include; a custom radio and Browse retain the library workflow. The default preference remains disabled with no selected file. The SPIM source requires a global `main` label, assumes the default exception vector, and retains unsupported `.set` directives and their MARS warnings. No source rewriting or implicit startup adaptation is performed.

**Open default `exceptions.s` in editor** previews the bundled source and closes the dialog without applying drafts, as stated in the dialog. Reference tabs carry a lock and read-only banner; edits, rename, Save/Save As, Cut/Paste, undo/redo, and replacement are unavailable. Selection, Copy, Find, individual Export, and Close remain available. **Copy to new file** creates an editable source with the complete licensed text. The reference is outside the writable library and excluded from bulk save/export and Auto Save. Recovery reinstates the canonical source and protection, ignoring saved changes/history for its identity. Opening the reference preserves loaded execution, bypasses Assemble on Open, and is available while running; copying waits until execution is idle. Direct Assemble is disabled on references, while setting-driven rebuilds retain the loaded user lead.

Add the Exceptions button last in the runtime/debug toolbar group and Memory Configuration immediately after ASCII in the display group. Both reuse their Settings command and availability; Memory uses a RAM-module glyph.

Missing sources retain the browser's `Source file "<name>" is not in the source library.` diagnostic rather than imitating `java.io.FileNotFoundException`. Assembly messages use virtual names and port the legacy filename-list wrapping and newlines exactly. The preamble is emitted after all sources have been read and tokenized successfully, before assembly, as in [RunAssembleAction](../../_legacy-app/mars/venus/RunAssembleAction.java); a missing handler therefore reports errors without that preamble.

Stable checkpoints retain the handler identity of the loaded assembly separately from live settings for future assemblies. Restoration rebuilds that original dependency list, then restores the hardware and history, preserving the current preference. Existing checkpoints without this field use their saved settings. Reset continues to use retained tokenized sources. The desktop publishes a setting change so an idle checkpoint captures the current preference without changing loaded code. Browser recovery retains the current persisted handler flag and filename when restoring an older stable checkpoint, including changes saved during an active run; the checkpoint still determines the handler belonging to loaded code.

## Consequences and evidence

The independent-selection workflow is recorded in [UI-0020](../deviations.md#ui-0020-exception-handler-selection-is-independent-of-enablement). The protected bundled workflow is recorded in [UI-0021](../deviations.md#ui-0021-bundled-read-only-exception-handler-reference). The added toolbar buttons extend [UI-0006](../deviations.md#ui-0006-command-access-and-added-bulk-controls). The source-library adaptations extend [UI-P0002](../deviations.md#ui-p0002-assembly-from-virtual-working-text). The former omitted-preamble difference in [UI-0015](../deviations.md#ui-0015-console-clearing-retention-and-assembly-notices) is retired. Framework-free assembly and simulator behavior remain in the existing engine/controller; dialog drafts stay with their mounted component, and settings commits stay with SimulationState.

The [Java probe](../../tests/oracle/exception-handler/README.md) captures the unchanged formatter, `performOK` outcomes and notifications, native missing-file diagnostic, and actual two-source trap/`eret` execution. [Session tests](../../tests/session/exception-handler.test.ts) compare the formatter, compatible legacy toggle/commit behavior, and machine state, and cover independent selection persistence, checkpoint reconstruction, and Reset. [Browser scenarios](../../tests/browser/settings/settings.spec.ts) exercise the real library chooser, drafts, gating, execution-time availability, working text, missing-library diagnostics, reload, bundled trap execution, protected reference recovery, editable copies, and toolbar placement. Swing presentation is established by source inspection, not by a captured interactive Swing session.
