# MARS-ts 1.0 deviations from MARS 4.5

## Baseline status and scope

This is the living catalog of implemented, user-impacting differences between MARS-ts and the final Java/Swing MARS 4.5 application. It was established on October 23, 2026 from the current [application source](../src/). **MARS-ts 1.0 has not been cut as a release; this catalog is not a declaration of completed parity.** At release, its reconciled contents become the formal 1.0 baseline. Subsequent enhancements are measured against that baseline, including its recorded differences from 4.5, rather than retroactively described as unfinished porting. [ADR 0012](adrs/0012-deviation-baseline.md) establishes this policy.

`src/` determines what MARS-ts currently does. The unchanged [legacy sources](../_legacy-app/README.md) determine the reference behavior; [oracle provenance](../tests/oracle/golden/provenance.json) identifies the source inputs used for captures, with the runtime and normalization documented in the [oracle guide](../tests/oracle/README.md). References to “4.5” below mean this repository's final-release reference implementation, not an independently verified binary hash of a downloaded JAR. GUI behavior is compared with Swing, not with incidental output from `MarsLaunch`; for example, ignoring the Exit2 process status in the GUI is legacy behavior, not a deviation.

Only implemented behavioral or functional differences belong here. Pending implementations remain in the [port plan](adrs/0000-port-plan.md) and [implementation guide](../IMPLEMENTATION.md#current-limitations), not in this catalog. Deliberate replacements or permanent scope exclusions are distinguishable from pending work and are included where they change the available workflow. Minor styling, icon artwork, implementation language, file moves, class extraction, dependency injection, and behavior-preserving ownership or subscription refactors are excluded. A light/dark **choice**, for example, is a capability; individual palette adjustments are not separate deviations.

The UI and Engine subsets each separate behavioral differences from browser/platform adaptations. The latter include both browser constraints and chosen browser-specific workflows; classification does not imply that every adaptation is technically unavoidable. Each entry links its deciding ADR, current implementation, legacy comparison, and available evidence. **Source comparison** records an observed difference, not an oracle-parity claim or a newly passing test. Where a focused regression is absent, that gap is explicit. Recording existing behavior does not invent historical authorization or require changing the implementation to fit older prose.

## UI subset

### Behavioral and functional deviations

#### UI-0001: Source-tab organization and renaming

The legacy [EditTabbedPane](../_legacy-app/mars/venus/EditTabbedPane.java) selects tabs and changes filenames through Save As. MARS-ts adds drag reordering, Alt+Shift+Left/Right reordering on a tab, per-tab close controls, and double-click/F2 inline rename. Rename commits current text and moves the saved library name atomically; it is not merely a label edit. Save As also offers a Rename toggle. Explicit renames require a nonempty `.asm` or `.s` basename, reject an identity owned by another open buffer, and confirm replacement of a closed saved source. Rename/reorder are unavailable during execution or a desktop modal.

Decisions: [ADR 0003](adrs/0003-browser-file-workflows.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [SourceTabs](../src/lib/venus/components/editor/SourceTabs.svelte), [SourceWorkspace](../src/lib/venus/state/SourceWorkspace.svelte.ts), and [Editor](../src/lib/editor/Editor.ts). Evidence: [rename](../tests/browser/rename.spec.ts) and [reorder](../tests/browser/reorder.spec.ts) browser scenarios; legacy source comparison.

#### UI-0002: Save eligibility, dirty state, and bulk file decisions

Legacy [EditTabbedPane](../_legacy-app/mars/venus/EditTabbedPane.java) can save a new empty source, saves only modified tabs in Save All and restores the original selection, and asks one combined dirty-file question for Close All. MARS-ts disables Save/Save As and skips automatic/bulk commits for a new zero-character buffer; a previously saved source can still be saved empty. New buffers are marked unsaved immediately, but closing an empty new buffer needs no individual save prompt. For saved sources, dirty state compares current text with the saved baseline, so undoing back to saved text clears it; legacy [FileStatus](../_legacy-app/mars/venus/FileStatus.java) tracks edit status rather than text equality.

MARS-ts Save All processes every eligible tab, including clean saved tabs, selects each as it goes, and leaves the last processed tab selected; canceling a save dialog abandons the remaining queue. Close All first asks for confirmation even for clean tabs, then resolves dirty buffers individually with Save/Discard/Cancel. Canceling partway does not reopen tabs already closed. Decisions: [ADR 0003](adrs/0003-browser-file-workflows.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [save eligibility](../src/lib/venus/utils/sources/savableSource.ts), [Editor](../src/lib/editor/Editor.ts), and [SourceWorkspace](../src/lib/venus/state/SourceWorkspace.svelte.ts). Evidence: [desktop workflows](../tests/browser/desktop.spec.ts) cover empty buffers, Save All, Close All, and cancellation; exact dirty-state and final-selection differences are source comparisons.

#### UI-0003: Edit selection and loaded execution are independent

With directory assembly off, legacy [EditTabbedPane's change listener](../_legacy-app/mars/venus/EditTabbedPane.java) clears Execute when selecting another source. MARS-ts can select, reorder, open, or close editor tabs while retaining the loaded program; enabling Assemble on Open still causes an Open action to assemble the selected source. Its Execute footer identifies that loaded source separately from the selected Edit source. Source edits still invalidate execution, including edits to another open source; selecting a tab alone does not. Close All closes documents without itself discarding the loaded machine.

Decisions: [ADR 0007](adrs/0007-desktop-session-recovery.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [SourceWorkspace](../src/lib/venus/state/SourceWorkspace.svelte.ts), [DesktopState](../src/lib/venus/state/DesktopState.svelte.ts), and [RunController](../src/lib/venus/RunController.ts). Evidence: loaded-program footer and tab-switch scenarios in [desktop](../tests/browser/desktop.spec.ts), [reorder](../tests/browser/reorder.spec.ts), and [recovery](../tests/browser/recovery.spec.ts); the Close All machine-retention distinction is source comparison.

#### UI-0004: Find/Replace defaults and matching boundaries

Legacy [Find/Replace](../_legacy-app/mars/venus/EditFindReplaceAction.java) starts case-sensitive. MARS-ts starts case-insensitive. Its Find Next wraps from a selection at end-of-file; legacy [JEditBasedTextArea.nextIndex](../_legacy-app/mars/venus/editors/jeditsyntax/JEditBasedTextArea.java) rejects a starting offset equal to the source length. With case sensitivity off, MARS-ts Replace accepts a selected match with different letter case; Java's replacement precondition still requires exact selected-text equality and the caret at the selection end. MARS-ts reports match offsets in the dialog. Its modal presentation is separately cataloged under UI-P0003.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [SourceSearch](../src/lib/venus/state/SourceSearch.svelte.ts). Evidence: source comparison; [desktop workflows](../tests/browser/desktop.spec.ts) exercise ordinary find/replace/undo, but do not pin all three boundary differences above.

#### UI-0005: Fixed editor/highlighting presets and a theme choice

The legacy [Editor settings](../_legacy-app/mars/venus/SettingsEditorAction.java) and [Highlighting settings](../_legacy-app/mars/venus/SettingsHighlightingAction.java) expose end-user customization. MARS-ts deliberately replaces those dialogs with bundled [editor](../src/lib/editor/editor-preset.json) and [runtime highlighting](../src/lib/venus/highlighting-preset.json) presets. Changes require editing the application assets and rebuilding; these are removed customization workflows, not pending dialogs. Line-number and display-base toggles remain interactive. A persisted light/dark switch is an added capability; its particular colors are outside this catalog.

Decision: [ADR 0002](adrs/0002-port-fidelity.md). Implementation: [SourceEditor](../src/lib/venus/components/editor/SourceEditor.svelte), [MenuBar](../src/lib/venus/components/shell/MenuBar.svelte), and [ThemeToggle](../src/lib/venus/components/shell/ThemeToggle.svelte). Evidence: [theme](../tests/browser/theme.spec.ts) and [desktop](../tests/browser/desktop.spec.ts) scenarios; legacy source comparison.

#### UI-0006: Command access and added bulk controls

Compared with [VenusUI](../_legacy-app/mars/venus/VenusUI.java), MARS-ts adds toolbar access to label visibility, program arguments, popup input, hexadecimal addresses/values, and ASCII, and puts line numbers in the editing toolbar. Shared Settings entries control the same preferences. Breakpoint toggle/clear actions add toolbar buttons beside their legacy Run menu group and keyboard commands, but have no clickable Bkpt column heading. Text Segment adds a button to clear the argument draft. Coproc 1 adds Select all/Select none for its eight condition flags; individual live flag editing already exists in [Coprocessor1Window](../_legacy-app/mars/venus/Coprocessor1Window.java) and is not itself a deviation.

Decisions: [ADR 0002](adrs/0002-port-fidelity.md), [ADR 0009](adrs/0009-program-arguments.md), and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [command catalog](../src/lib/venus/utils/commands/actions.ts), [Settings catalog](../src/lib/venus/utils/commands/settings.ts), [TextSegmentPane](../src/lib/venus/components/debugger/TextSegmentPane.svelte), and [RegisterBanksPane](../src/lib/venus/components/debugger/RegisterBanksPane.svelte). Evidence: [desktop](../tests/browser/desktop.spec.ts), [program arguments](../tests/browser/program-arguments.spec.ts), and [registers](../tests/browser/registers.spec.ts) scenarios. Icon shapes and separator spacing are not catalog entries.

#### UI-0007: Pane arrangement and visibility controls

Legacy [ExecutePane](../_legacy-app/mars/venus/ExecutePane.java) hosts movable, resizable, maximizable/iconifiable Swing internal windows. MARS-ts uses a fixed Text/Labels/Data arrangement with split dividers rather than those independent window operations. Labels starts visible by default. It adds a Registers visibility switch that removes the sidebar and divider without changing the machine, and a Restore full Data Segment height action. Editor/messages, register width, and Data Segment height have pointer and keyboard resize controls. Table columns follow the web layout rather than the drag-reorderable Text Segment columns in [TextSegmentWindow](../_legacy-app/mars/venus/TextSegmentWindow.java).

Decisions: [ADR 0002](adrs/0002-port-fidelity.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [VenusUI](../src/lib/venus/VenusUI.svelte), [ExecutePane](../src/lib/venus/components/debugger/ExecutePane.svelte), and [DataSegmentPane](../src/lib/venus/components/debugger/DataSegmentPane.svelte). Evidence: pane-resize, restore-height, and sidebar scenarios in [desktop](../tests/browser/desktop.spec.ts), [execution](../tests/browser/execution.spec.ts), and [registers](../tests/browser/registers.spec.ts); legacy source comparison. Mere dimensions and styling are excluded.

#### UI-0008: Label selection coordinates multiple tables

Legacy [LabelsWindow](../_legacy-app/mars/venus/LabelsWindow.java) routes a text label to Text Segment and a data label to Data Segment. MARS-ts text-label selection reveals both the instruction and its word in the Data Segment text range, including kernel text. The Labels row and destinations share a persistent selection independent of PC/write highlighting; selecting the same label again clears it. Data-label paging uses floor division, correcting the Java [DataSegmentWindow](../_legacy-app/mars/venus/DataSegmentWindow.java) truncated-division behavior for targets just below a dynamic `$gp`/`$sp` base. Selection never moves the simulated PC.

Decision: [ADR 0002](adrs/0002-port-fidelity.md); reload persistence is [ADR 0007](adrs/0007-desktop-session-recovery.md). Implementation: [ExecuteView](../src/lib/venus/components/debugger/ExecuteView.svelte.ts) and [memory navigation](../src/lib/venus/utils/debugger/memoryView.ts). Evidence: text/data label and below-stack-base scenarios in [execution](../tests/browser/execution.spec.ts), plus [selection recovery](../tests/browser/recovery.spec.ts).

#### UI-0009: PC following and source navigation

Legacy [TextSegmentWindow.highlightStepAtAddress](../_legacy-app/mars/venus/TextSegmentWindow.java) scrolls as needed to make an instruction visible. MARS-ts holds the opening page until its last fully visible row, then centers the current instruction below sticky headers, clamped at the table ends. Assembly/Reset restart that behavior. Unmodified Source cells also act as links into an already-open source buffer and focus its line; the legacy table displays source text without that editor-link action. A closed source is not implicitly reopened by this action, and modified instructions display the modification marker instead of a source link.

Decisions: [ADR 0002](adrs/0002-port-fidelity.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [TextSegmentPane](../src/lib/venus/components/debugger/TextSegmentPane.svelte) and [SourceWorkspace.showSource](../src/lib/venus/state/SourceWorkspace.svelte.ts). Evidence: opening/center/final-page and Source-cell scenarios in [execution](../tests/browser/execution.spec.ts); legacy source comparison.

#### UI-0010: Memory page stride

Both versions display sixteen rows of eight words. Legacy [DataSegmentWindow](../_legacy-app/mars/venus/DataSegmentWindow.java) advances Previous/Next by half a table, 256 bytes, to retain overlapping context. MARS-ts advances by the full 512-byte page, with clamping at address limits. This changes which words remain visible after paging, independently of the table's visual size.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [DataSegmentPane](../src/lib/venus/components/debugger/DataSegmentPane.svelte) and [memoryView](../src/lib/venus/utils/debugger/memoryView.ts). Evidence: source comparison; [memory-view tests](../src/lib/venus/utils/debugger/memoryView.test.ts) and [browser paging scenarios](../tests/browser/execution.spec.ts) exercise the current navigation rules.

#### UI-0011: Editing and setting availability during execution

Legacy register, coprocessor, data, and enabled text-code table editors synchronize changes between instructions; their editability predicates do not reject an active run. MARS-ts makes numeric register, memory, and instruction-code cells read-only while running, including while waiting for input. Individual Coproc 1 condition flags and their added bulk actions remain editable. The port also disables all exposed engine-setting toggles during execution; [VenusUI.setMenuStateRunning](../_legacy-app/mars/venus/VenusUI.java) explicitly disables delayed branching and memory configuration, leaving other setting actions available. Display-only toggles remain live. MARS-ts keeps its Copy command available while running where Java disables the Edit Copy action.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [DesktopState](../src/lib/venus/state/DesktopState.svelte.ts), [RegisterBanksPane](../src/lib/venus/components/debugger/RegisterBanksPane.svelte), [DataSegmentPane](../src/lib/venus/components/debugger/DataSegmentPane.svelte), and [TextSegmentPane](../src/lib/venus/components/debugger/TextSegmentPane.svelte). Legacy predicates: [RegistersWindow](../_legacy-app/mars/venus/RegistersWindow.java), [Coprocessor0Window](../_legacy-app/mars/venus/Coprocessor0Window.java), [Coprocessor1Window](../_legacy-app/mars/venus/Coprocessor1Window.java), [DataSegmentWindow](../_legacy-app/mars/venus/DataSegmentWindow.java), and [TextSegmentWindow](../_legacy-app/mars/venus/TextSegmentWindow.java). Evidence: source comparison and [settings](../tests/browser/settings.spec.ts)/[condition-flag](../tests/browser/registers.spec.ts) scenarios; not every editability combination has a focused regression.

#### UI-0012: Assembly-policy changes invalidate loaded execution

Legacy [extended-instruction](../_legacy-app/mars/venus/SettingsExtendedAction.java), [warnings-as-errors](../_legacy-app/mars/venus/SettingsWarningsAreErrorsAction.java), and [start-at-main](../_legacy-app/mars/venus/SettingsStartAtMainAction.java) actions change the stored setting without clearing the loaded program. MARS-ts invalidates execution when these choices change and requires assembly again. Delayed-branching and memory-layout changes reassemble loaded code, while self-modifying code changes the access policy without resetting execution; those latter workflows follow the legacy actions and are not additional deviations. The UI also enables Reset only when the loaded statement list is nonempty, although the controller can reset a data-only program; legacy [VenusUI.setMenuStateRunnable](../_legacy-app/mars/venus/VenusUI.java) enables Reset after successful assembly without that statement-count condition.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [Settings catalog](../src/lib/venus/utils/commands/settings.ts), [SimulationState](../src/lib/venus/state/SimulationState.svelte.ts), and [DesktopState](../src/lib/venus/state/DesktopState.svelte.ts). Evidence: source comparison; [settings scenarios](../tests/browser/settings.spec.ts) cover implemented settings, but the invalidation and data-only Reset differences are not all individually pinned.

#### UI-0013: Run-speed interaction

Legacy [RunSpeedPanel](../_legacy-app/mars/venus/RunSpeedPanel.java) has positions 0–40, with five adjacent positions all meaning unlimited. MARS-ts presents one position per distinct speed, collapses unlimited to one endpoint, adds increment/decrement buttons, and shows the control only in Execute. Finite rates remain 0.05–30 instructions/second and unlimited retains the engine sentinel 40; there is no new instruction timing scale. Browser persistence retains the legacy-compatible position representation.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [SpeedSlider](../src/lib/venus/components/shell/SpeedSlider.svelte) and [run-speed rules](../src/lib/venus/utils/execution/runSpeed.ts). Evidence: [speed scenarios](../tests/browser/speed.spec.ts), [run-speed tests](../src/lib/venus/utils/execution/runSpeed.test.ts), and legacy source comparison.

#### UI-0014: Live breakpoint controls at finite speeds, locked at maximum speed

Legacy Go snapshots breakpoints when it starts; later checkbox edits do not update that run. MARS-ts forwards checkbox, suspend/restore, and clear changes into an active finite-speed Go. At maximum speed it disables those UI mutations **whether or not a program runs**, with tooltips advising the user to lower the speed; the current breakpoint list, including changes made earlier at finite speed, still stops execution. Unlike MARS 4.5, breakpoints cannot be edited at the default maximum speed even while stopped. Lowering the speed, including during a run, unlocks the controls. The engine capability and exact post-instruction timing are cataloged separately in ENG-0001. A pending Step does not acquire Go breakpoint behavior. While breakpoints are suspended, legacy [TextSegmentWindow](../_legacy-app/mars/venus/TextSegmentWindow.java) grays the Bkpt checkboxes and disables their editor; MARS-ts grays them the same way but keeps them editable, so the list can be adjusted before Toggle all breakpoints restores it. Legacy [RunClearBreakpointsAction](../_legacy-app/mars/venus/RunClearBreakpointsAction.java) clears immediately, as MARS-ts does by default. A new, initially off **Prompt to clear all breakpoints** setting, directly after Clear all outputs on Go, instead asks for confirmation from the toolbar, Run menu, and Ctrl+K alike; Cancel or dismissal keeps every breakpoint. The confirmation's **Keep showing this warning** checkbox is the same persisted preference, so turning it off there stops later prompts. Confirming during a finite-speed Go applies to that run as any other clear does, and does nothing if maximum speed has locked breakpoints in the meantime.

Decision: [ADR 0011](adrs/0011-in-flight-breakpoints.md). Implementation: [DesktopState.breakpointsFrozen](../src/lib/venus/state/DesktopState.svelte.ts), [TextSegmentPane](../src/lib/venus/components/debugger/TextSegmentPane.svelte), and [SimulationState](../src/lib/venus/state/SimulationState.svelte.ts). Legacy comparison: [RunGoAction](../_legacy-app/mars/venus/RunGoAction.java) and [Simulator](../_legacy-app/mars/simulator/Simulator.java). Evidence: [execution scenarios](../tests/browser/execution.spec.ts), including grayed but enabled suspended checkboxes and the opt-in Clear all breakpoints confirmation, and [controller tests](../tests/session/globals-controller.test.ts). This entry describes the current speed gate, not removal of breakpoint execution at maximum speed.

#### UI-0015: Console clearing, retention, and assembly notices

Legacy [MessagesPane](../_legacy-app/mars/venus/MessagesPane.java) has per-console clearing and, after an append exceeds 1,000,000 characters, removes the oldest 100,000 characters from either console. MARS-ts adds Clear All and shortcuts for selected/all output; clearing preserves pending input. Run I/O retains exactly the most recent 1,000,000 characters, while Mars Messages currently has no corresponding truncation. The latter is an observed current behavior, not a new guarantee of unlimited storage. MARS-ts also omits the legacy [RunAssembleAction](../_legacy-app/mars/venus/RunAssembleAction.java) filename-list preamble, while retaining translated diagnostics and assembly-completion notices.

An optional, initially off Clear all outputs on Go preference clears both consoles only before a fresh Go after assembly/Reset; resuming and Step do not clear them. Decisions: [ADR 0008](adrs/0008-clear-outputs-on-go.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [MessagesPane](../src/lib/venus/components/debugger/MessagesPane.svelte) and [SimulationState](../src/lib/venus/state/SimulationState.svelte.ts). Evidence: [console controls](../tests/browser/controls.spec.ts) and [fresh/resumed Go](../tests/browser/execution.spec.ts) scenarios; retention and omitted preamble are source comparisons without dedicated threshold/preamble regressions.

#### UI-0016: Register-edit validation feedback

Legacy register and coprocessor table models replace invalid input with `INVALID` in the edited cell. MARS-ts restores the displayed hardware value and shows an explanatory error beneath the register table. It trims surrounding whitespace before parsing manual numeric edits. Data/code edits still use `INVALID` for numeric parse failures and report other memory-write failures visibly, where Java's data editor silently returns on an address error. These are UI input/feedback differences; the engine parsers and memory-protection rules are unchanged.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [RegisterBanksPane](../src/lib/venus/components/debugger/RegisterBanksPane.svelte) and [ExecuteView.changeWord](../src/lib/venus/components/debugger/ExecuteView.svelte.ts). Legacy comparison: [RegistersWindow](../_legacy-app/mars/venus/RegistersWindow.java), [Coprocessor1Window](../_legacy-app/mars/venus/Coprocessor1Window.java), and [DataSegmentWindow](../_legacy-app/mars/venus/DataSegmentWindow.java). Evidence: source comparison; no dedicated complete invalid-input comparison is claimed.

#### UI-0017: Help navigation, examples, and hover filtering

Legacy [HelpHelpAction](../_legacy-app/mars/venus/HelpHelpAction.java) presents tabbed help in a separate window that opens on its MIPS tab. The MARS-ts Help command opens a tabbed browser on a short overview tab, followed by MIPS, MARS, Bugs/Comments, and Acknowledgements tabs that keep the legacy order and nesting for the bundled articles. Legacy Bugs/Comments names the Missouri State web page and an author email address; MARS-ts directs reports to its GitHub repository, Issues, and Discussions pages and keeps the original contacts only as history. Each legacy Help action builds a new window on the MIPS tab, while MARS-ts reopens on the last selected tab and nested articles. Session recovery retains that selection across reloads and reopens the browser after a reload if it was open; legacy windows do not survive an application restart. An article reopens at the top after a tab switch, where Swing retains each tab's scroll position within one window. The Help menu additionally opens each article individually. Articles are adapted to current browser workflows, with legacy history/extension material explicitly identified. Every displayed code block has Copy and Open as new file actions; opening creates a separate source and is disabled during execution. Loading/failure feedback accompanies on-demand articles. This catalogs the implemented Help workflow, not missing legacy help sections.

The editor's implemented instruction hover also differs: it displays all registry matches even when extended instructions are disabled. Legacy [MIPSTokenMarker.getTokenExactMatchHelp](../_legacy-app/mars/venus/editors/jeditsyntax/tokenmarker/MIPSTokenMarker.java) filters to basic instructions in that mode and identifies pseudo-only names as non-basic. Decisions: [ADR 0002](adrs/0002-port-fidelity.md), [ADR 0007](adrs/0007-desktop-session-recovery.md), and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [HelpBrowser](../src/lib/help/HelpBrowser.svelte), [HelpArticle](../src/lib/help/HelpArticle.svelte), [article catalog](../src/lib/help/articles.ts), and [SourceEditor](../src/lib/venus/components/editor/SourceEditor.svelte). Evidence: [Help](../tests/browser/help.spec.ts) and [ordinary hover](../tests/browser/desktop.spec.ts) scenarios; disabled-pseudo hover filtering is source comparison without a dedicated regression.

#### UI-0018: Editor undo retention

Legacy [JEditBasedTextArea](../_legacy-app/mars/venus/editors/jeditsyntax/JEditBasedTextArea.java) uses Swing's default `UndoManager`, whose limit is 100 edits; the legacy application does not change that limit. MARS-ts retains its source revision undo/redo arrays without an application-level count limit, so older revisions remain reachable beyond that threshold. Available memory and browser recovery storage still constrain retention; this is not a durability or unlimited-capacity guarantee. It concerns source editing, not the separately bounded simulator Backstep history.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [Editor](../src/lib/editor/Editor.ts). Evidence: source comparison and a local Java probe of `new javax.swing.undo.UndoManager().getLimit()` returning `100`; [editor tests](../src/lib/editor/Editor.test.ts) cover ordinary undo/redo, but do not pin retention beyond that threshold.

#### UI-0019: Breakpoints survive an identical rebuild

Legacy [RunAssembleAction](../_legacy-app/mars/venus/RunAssembleAction.java) calls [TextSegmentWindow.setupTable](../_legacy-app/mars/venus/TextSegmentWindow.java) on every successful assemble, which rebuilds the table with unchecked breakpoints and re-enables them. MARS-ts keeps the breakpoint list, and whether it is suspended, when the new build's loaded programs have the same filenames, instruction addresses, and binary statements as the most recent successful build; source changes that leave machine code unchanged, such as comments, therefore keep breakpoints. Any other successful build, including one moved by a memory-configuration change, clears and re-enables them as in MARS 4.5. A failed assembly changes neither the breakpoints nor the remembered build, and a build restored by desktop recovery counts as the most recent one.

Decision: [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [SimulationState](../src/lib/venus/state/SimulationState.svelte.ts). Evidence: [execution scenario](../tests/browser/execution.spec.ts) covering identical, comment-only, and changed rebuilds; retention across a recovery reload is source comparison without a focused regression.

### Browser and platform adaptations

#### UI-P0001: Browser source library, transfers, and automatic commits

Legacy Open/Save operate on OS files. MARS-ts Open/Save operate on complete source records in an origin/profile-local library; no native file handle is retained. Import reads one or more `.asm`/`.s` files and ZIP archives into that library, where legacy MARS has no Import command and no archive support. Each archive contributes its `.asm`/`.s` entries under their normalized folder paths, so relative includes keep resolving. Every selection opens a same-tab summary listing the sources to import (noting the archive, saved-name replacements, and open buffers with unsaved edits, which block the import) and every skipped file or entry with its reason: another extension, an unsafe path, a name repeated within the selection, an unreadable, encrypted, ZIP64, or corrupt archive or entry, or a source above 16 MiB. Confirming commits only the valid sources; there is no native All Files escape. Export downloads current text without marking it saved; Export All merges library sources with open drafts, prefers drafts, flattens paths, disambiguates duplicate basenames, and downloads a ZIP. Browser settings choose the download destination. A non-dismissable spinner dialog covers the desktop from the moment the Import picker or Export save picker opens, reading "Waiting for file selection…" or "Waiting for save location…". Once the browser reports the outcome, it reads "Attempting import…" or "Exporting…" for a selection, or "Canceling import…" or "Canceling export…" for a cancellation, never both. It is released as soon as the page is visible and focused again, adding no delay of its own, so the browser's or OS's own return of control is covered rather than exposed as an unresponsive desktop. In Chromium-based browsers Export saves through the browser's save picker, which appears on every export; other browsers use a download link, whose save-prompt cancellation cannot be relayed. Open also offers confirmed library deletion, closing affected tabs only after storage succeeds. While no source is open and the library is empty, the Edit pane prompts to create a file with New or bring one in with Import, where the legacy empty editor area is blank.

A new, initially off Auto Save toggle commits eligible changed buffers without a Save action. Separate draft backups retain unsaved text even with Auto Save off; conflicting recovered drafts disable automatic commits and preserve both versions. Quota/access failures remain visible and do not mark failed saves clean. This storage and recovery workflow differs from native file durability and cross-process OS file access. Decision: [ADR 0003](adrs/0003-browser-file-workflows.md). Implementation: [SourceLibrary](../src/lib/browser/SourceLibrary.ts), [SourceWorkspace](../src/lib/venus/state/SourceWorkspace.svelte.ts), [FileImporter](../src/lib/venus/components/transfers/FileImporter.svelte), the [import planner](../src/lib/browser/sourceImport.ts) and [ZIP codec](../src/lib/browser/zip.ts), and [downloads](../src/lib/browser/download.ts). Legacy comparison: [EditTabbedPane](../_legacy-app/mars/venus/EditTabbedPane.java). Evidence: [desktop workflows](../tests/browser/desktop.spec.ts), [source extensions](../tests/browser/source-extensions.spec.ts), [source-library tests](../src/lib/browser/SourceLibrary.test.ts), [import-planner tests](../src/lib/browser/sourceImport.test.ts), and [ZIP tests](../src/lib/browser/zip.test.ts); the save-prompt wait is exercised with simulated focus events, not a native browser prompt.

#### UI-P0002: Assembly from virtual working text

Legacy [RunAssembleAction](../_legacy-app/mars/venus/RunAssembleAction.java) saves an edited current file and can discover every assembly file in its native directory. MARS-ts assembles the selected working buffer without an implicit Save, resolves explicit includes from current open text before saved library text, and performs no directory discovery or automatic inclusion of unrelated tabs. The directory/assemble-all UI is deliberately removed and its persisted engine preference is reset on startup. Virtual filenames are normalized relative names within the library; source lookup uses `/` paths rather than OS filesystem semantics.

Decisions: [ADR 0002](adrs/0002-port-fidelity.md) and [ADR 0003](adrs/0003-browser-file-workflows.md). Implementation: [SimulationState](../src/lib/venus/state/SimulationState.svelte.ts), [SourceWorkspace](../src/lib/venus/state/SourceWorkspace.svelte.ts), and [SourceLibrary](../src/lib/browser/SourceLibrary.ts). Evidence: active-source, unsaved-include, closed-include, and retired-preference cases in [execution scenarios](../tests/browser/execution.spec.ts). Engine multi-program assembly remains available; its algorithm is not a deviation.

#### UI-P0003: Same-tab modal interaction and console input

Application dialogs use one same-tab HTML modal with contained focus, Escape/backdrop dismissal, and focus restoration. This includes Find/Replace and Help, which are modeless in legacy [EditFindReplaceAction](../_legacy-app/mars/venus/EditFindReplaceAction.java) and [HelpHelpAction](../_legacy-app/mars/venus/HelpHelpAction.java); users cannot leave those MARS-ts dialogs open while interacting with the rest of the desktop. External resources and the license may still open ordinary browser tabs. Native Import remains a browser file picker.

Console reads use a separate inline input field with Submit/Stop controls rather than temporarily making the Run I/O output document editable as [MessagesPane](../_legacy-app/mars/venus/MessagesPane.java) does. Popup input uses the same-tab modal; Cancel, Escape, close, or backdrop dismissal requests Stop and settles the pending syscall with the current draft. Java's popup returns the `JOptionPane` input value on dismissal rather than issuing that Stop request. Prompt strings, normal echo, newline handling, and syscall value conversion retain their translated contracts. Decisions: [ADR 0003](adrs/0003-browser-file-workflows.md), [ADR 0004](adrs/0004-cooperative-simulation.md), and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [Modal](../src/lib/venus/components/dialogs/Modal.svelte), [RunInputDialog](../src/lib/venus/components/dialogs/RunInputDialog.svelte), [MessagesPane](../src/lib/venus/components/debugger/MessagesPane.svelte), and [SimulationState](../src/lib/venus/state/SimulationState.svelte.ts). Evidence: modal/clipboard scenarios in [desktop](../tests/browser/desktop.spec.ts) and [input/Stop](../tests/browser/execution.spec.ts); Swing dismissal behavior is source comparison.

#### UI-P0004: Keyboard ownership and clipboard permissions

Native [VenusUI](../_legacy-app/mars/venus/VenusUI.java) uses the OS menu modifier for New/Close. MARS-ts uses Alt/Option+N and Alt/Option+W to avoid common browser window/tab commands, adds Alt/Option+Shift+W for Close All (which has no legacy shortcut), uses Alt/Option+T rather than the legacy Ctrl+T for Toggle all breakpoints, adds Ctrl+Shift+S for Save As and Ctrl+Shift+Z as another Redo chord, and accepts Meta for Ctrl commands. Delivered application shortcuts are captured across text fields; disabled or modal-blocked commands still suppress their browser default without executing. Browser/OS-reserved events that never reach the page remain outside app control. Clipboard buttons use permission-dependent browser APIs and report denial; native text shortcuts remain available. Unlike the synchronous Swing editor action, browser Cut/Paste awaits the clipboard and abandons its source mutation if the captured source snapshot has been replaced or execution has started. Moving the caret alone retains the originally captured replacement range.

Decisions: [ADR 0003](adrs/0003-browser-file-workflows.md), [ADR 0006](adrs/0006-object-lifetime-management.md), and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [command catalog](../src/lib/venus/utils/commands/actions.ts), [desktop keyboard binding](../src/lib/venus/hooks/useDesktopKeyboard.ts), and [SourceWorkspace](../src/lib/venus/state/SourceWorkspace.svelte.ts). Evidence: [keyboard/control](../tests/browser/controls.spec.ts), [Option-key](../tests/browser/desktop.spec.ts), and [clipboard lifetime](../tests/browser/lifetime.spec.ts) scenarios; caret-only movement while awaiting clipboard is source comparison. Added console and tab-reorder shortcuts belong to their corresponding UI entries.

#### UI-P0005: Persistent desktop and stable machine recovery

Java preferences retain settings, but the legacy application does not serialize this complete open desktop and live machine for restart. MARS-ts restores drafts, saved baselines, matching per-source undo/redo, selected panes, caret/viewport, memory page, breakpoints, label selection, argument draft, console buffers, and the loaded program's last stable checkpoint. Reload during execution restores the preceding stable machine and its paired console output, without replaying instructions or automatically resuming; intervening output/input is not a resumable checkpoint. The source selected in Edit can differ from the restored executable.

Storage is scoped to an origin/profile, can be cleared or denied, and is shared by tabs without synchronization; the most recent successful record wins. Failed writes retain in-memory work and the last saved recovery record. Decisions: [ADR 0003](adrs/0003-browser-file-workflows.md) and [ADR 0007](adrs/0007-desktop-session-recovery.md). Implementation: [DesktopPersistence](../src/lib/venus/state/DesktopPersistence.svelte.ts), [DesktopSession](../src/lib/browser/DesktopSession.ts), and [browser preferences](../src/lib/browser/README.md). Legacy comparison: [Settings](../_legacy-app/mars/Settings.java), [Editor](../_legacy-app/mars/venus/Editor.java), and [RunResetAction](../_legacy-app/mars/venus/RunResetAction.java). Evidence: [recovery](../tests/browser/recovery.spec.ts), [desktop](../tests/browser/desktop.spec.ts), and [checkpoint tests](../tests/session/globals-controller.test.ts). ENG-P0003 describes the supporting engine contract.

#### UI-P0006: Launch, printing, and application lifetime

MARS-ts enters the desktop directly, with only a transient initialization indicator while restoration completes. It does not reproduce the native [splash](../_legacy-app/mars/MarsSplashScreen.java). The legacy Print menu action is replaced by browser printing of the current source using a print-only source view; Exit is omitted and closing documents leaves the page open. A dirty-source unload guard delegates the final leave/reload prompt to the browser. The shipped app has no `MarsLaunch` command-line interface; that is a settled scope exclusion, not an unfinished feature. The Java CLI remains oracle infrastructure.

Decisions: [ADR 0000](adrs/0000-port-plan.md), [ADR 0002](adrs/0002-port-fidelity.md), and [ADR 0003](adrs/0003-browser-file-workflows.md). Implementation: [root page](../src/routes/+page.svelte), [VenusUI](../src/lib/venus/VenusUI.svelte), [keyboard/unload binding](../src/lib/venus/hooks/useDesktopKeyboard.ts), and [file commands](../src/lib/venus/utils/commands/actions.ts). Legacy comparison: [MarsLaunch](../_legacy-app/mars/MarsLaunch.java), [FilePrintAction](../_legacy-app/mars/venus/FilePrintAction.java), and [FileExitAction](../_legacy-app/mars/venus/FileExitAction.java). Evidence: direct-launch and Close All [desktop scenarios](../tests/browser/desktop.spec.ts); print/unload platform behavior is source comparison, not a claimed automated OS-dialog test.

#### UI-P0007: Installable offline application and release activation

The JAR runs as a local Java application. MARS-ts ships static web assets, can be installed as a PWA, and caches its application resources after a successful online load. It requires a suitable origin; directly opening `index.html` through `file://` is unsupported. A replacement service worker waits for old controlled tabs to close rather than forcing an active machine onto new assets. Activation deletes every other CacheStorage cache on the origin, not only older MARS-prefixed caches; a shared origin would therefore expose unrelated caches to deletion. Cache updates do not migrate or erase localStorage sources and recovery. Hosted and localhost installations retain separate origin data.

Decisions: [ADR 0005](adrs/0005-coolify-deployment.md) and [ADR 0010](adrs/0010-pwa-offline-support.md). Implementation: [service worker](../src/service-worker/index.ts) and [root layout](../src/routes/+layout.svelte), with the [manifest](../static/manifest.webmanifest). Evidence: [PWA browser scenario](../tests/browser/pwa.spec.ts) covers the manifest/icons only; ADR 0010 records production-preview and deployed-site manual offline checks, not a committed automated offline guarantee.

#### UI-P0008: Memory dump files

Legacy [FileDumpMemoryAction](../_legacy-app/mars/venus/FileDumpMemoryAction.java) uses a Swing segment/format dialog and native file chooser. MARS-ts uses its existing same-tab modal and opens the browser/OS save picker for each dump, with a download-link fallback whose destination and cancellation reporting depend on browser settings. Picker cancellation preserves the selections; write failures abort the stream and remain visible for retry. No file handle or source-library record is retained. The suggested filename uses the assembled build’s source basename plus its segment and output extension (for example, `main.text.hex`), even when another source is selected in Edit. Binary suggests `.bin`, hexadecimal text and Intel HEX `.hex`, and other text formats `.txt`; legacy only specifies Intel HEX's extension. Text is deterministic UTF-8/LF instead of Java host defaults. The same populated `.text`/`.data` ranges and six enabled formats are offered, with an empty-state message when neither range is populated; the Java dialog assumes at least one range exists. Output reflects live idle memory after assembly or execution.

Decision: [ADR 0003](adrs/0003-browser-file-workflows.md). Implementation: [dump encoders](../src/lib/engine/dump/README.md), [dump dialog](../src/lib/venus/components/dialogs/DumpMemoryDialog.svelte), and [save lifecycle](../src/lib/browser/FileDownload.ts). Evidence: [Java byte fixtures](../tests/oracle/dump-units/README.md), [encoder comparisons](../src/lib/engine/dump/dump.test.ts), and [browser scenarios](../tests/browser/dump.spec.ts) cover all format selections, raw binary download, picker cancellation, write failure/retry, dismissal, and live post-execution data. Native OS dialogs are represented by picker stubs; download fallback is exercised through Playwright's actual download event.

## Engine subset

### Behavioral and functional deviations

#### ENG-0001: Replacing an active run's breakpoints

Legacy [Simulator.SimThread](../_legacy-app/mars/simulator/Simulator.java) retains Go's initial breakpoint array. MARS-ts adds `Simulator.updateBreakpoints`, replacing the active list with a sorted copy (empty/null means none), and ignores the call while idle. `RunController` forwards updates only for its active Go; Step retains its step-limit result. This is an execution-control extension, not a new instruction or altered breakpoint comparison rule. The UI imposes the finite-speed editing gate described in UI-0014; the engine API itself is not speed-gated.

The check remains **after an instruction/syscall and delayed-branch processing**, following Stop/Pause and preceding the step limit. A replacement made during a timer/batch yield is used at the next such check, not by an extra pre-fetch check: an instruction already selected by the PC may execute before its newly added breakpoint is tested. A replacement during pending input is checked after that syscall completes. Decision: [ADR 0011](adrs/0011-in-flight-breakpoints.md). Implementation: [Simulator](../src/lib/engine/simulator/Simulator.ts) and [RunController](../src/lib/venus/RunController.ts). Evidence: [simulator](../src/lib/engine/simulator/Simulator.test.ts), [controller](../tests/session/globals-controller.test.ts), and [browser](../tests/browser/execution.spec.ts) regressions establish the added contract; [oracle simulator fixtures](../tests/oracle/simulator-units/README.md) establish only the legacy start-time behavior they capture.

### Browser and platform adaptations

#### ENG-P0001: Cooperative execution and asynchronous input

Java [Simulator](../_legacy-app/mars/simulator/Simulator.java) uses a SwingWorker and blocking [SystemIO](../_legacy-app/mars/util/SystemIO.java) reads. MARS-ts simulation entry points return promises and await host-provided input/scheduling. Ordinary instructions remain synchronous; an initial yield, limited-speed delays, and batches of up to 1,000 instructions at unlimited speed let the browser process events. Browser scheduling affects wall-clock responsiveness rather than introducing a new MIPS timing model. A stop request releases pending input, but execution ownership remains held until the operation settles, so Reset or a second run cannot replace a still-active machine.

Decision: [ADR 0004](adrs/0004-cooperative-simulation.md). Implementation: [Simulator](../src/lib/engine/simulator/Simulator.ts), [SystemIO](../src/lib/engine/io/SystemIO.ts), and the [browser scheduling host](../src/lib/venus/state/SimulationState.svelte.ts). Evidence: [simulator oracle](../tests/oracle/simulator-units/README.md), [async/Stop tests](../src/lib/engine/simulator/Simulator.test.ts), and [execution workflows](../tests/browser/execution.spec.ts). The platform contract is additional; covered instruction/check ordering is compared separately against the oracle.

#### ENG-P0002: Fatal host operations raise errors instead of exiting Java

Java process exits in [ProgramArgumentList](../_legacy-app/mars/simulator/ProgramArgumentList.java), [SyscallLoader](../_legacy-app/mars/mips/instructions/SyscallLoader.java), and the failed-restore path of [BackStepper](../_legacy-app/mars/simulator/BackStepper.java) cannot terminate the browser host. MARS-ts preserves the diagnostic boundary and throws an owner-visible error. Failed argument setup executes no instruction and does not roll back partial writes. Invalid syscall configuration fails initialization after reporting its diagnostics. A fatal Backstep restore reports through the injected host and aborts that operation; this is not a promise of transactional rollback or a usable recovered machine after failure.

Decisions: [ADR 0009](adrs/0009-program-arguments.md) and [ADR 0012](adrs/0012-deviation-baseline.md). Implementation: [ProgramArgumentList](../src/lib/engine/simulator/ProgramArgumentList.ts), [SyscallLoader](../src/lib/engine/syscalls/SyscallLoader.ts), [BackStepper](../src/lib/engine/simulator/BackStepper.ts), and [Globals](../src/lib/engine/Globals.ts). Evidence: [argument fatal-path capture](../tests/oracle/program-arguments-units/README.md) and [argument comparisons](../tests/session/program-arguments.test.ts); [syscall tests](../src/lib/engine/syscalls/core-syscalls.test.ts) and [Backstep tests](../src/lib/engine/simulator/BackStepper.test.ts) exercise configuration/fatal hooks. No equivalence between throwing and a JVM process exit is claimed.

#### ENG-P0003: Portable machine checkpoints

MARS-ts adds capture/restore APIs for sparse memory, registers, settings, delayed branches, pending interrupts, controller state, and bounded Backstep history. Legacy Reset reassembles retained programs; it does not provide this serialized restart contract. Restoration rebuilds captured assembly metadata, then silently restores validated hardware and history without executing instructions, replaying I/O, or creating undo entries. Pending reads, timers, promises, and an active run are never serialized. This platform extension supports UI-P0005; moving static fields to instances or extracting the state owners is not separately cataloged.

Decision: [ADR 0007](adrs/0007-desktop-session-recovery.md). Implementation: [RunCheckpoint](../src/lib/venus/RunCheckpoint.ts), [RunController](../src/lib/venus/RunController.ts), and engine capture/restore methods in [Memory](../src/lib/engine/hardware/memory/Memory.ts), [Settings](../src/lib/engine/Settings.ts), and [BackStepper](../src/lib/engine/simulator/BackStepper.ts). Legacy comparison: [RunResetAction](../_legacy-app/mars/venus/RunResetAction.java) and [BackStepper](../_legacy-app/mars/simulator/BackStepper.java). Evidence: [checkpoint round trips](../tests/session/globals-controller.test.ts), [argument recovery](../tests/session/program-arguments.test.ts), and [browser recovery](../tests/browser/recovery.spec.ts), rather than a claim that Java already had this feature.

## Audit coverage and release maintenance

The initial audit inspected the route and service-worker entry points, source/editor and browser adapters, Venus command/state owners, debugger/dialog/Help surfaces, engine composition and subsystem contracts, existing ADRs 0000–0011, and their linked tests and Java counterparts. It found no additional established instruction-set, numeric, assembler, memory-layout, or deterministic syscall-semantic divergence to catalog beyond the execution-control and platform contracts above. This is an inventory of evidenced differences, not an exhaustive proof over every program or every Swing interaction. Existing oracle suites remain the authority for the inputs they cover; unimplemented features and untested cases do not become accepted deviations by omission.

Before the 1.0 release, reconcile every entry against the release source, record its release identifier/revision and evidence, resolve any unapproved behavioral choices, and distinguish remaining evidence gaps from verified comparisons. Keep stable entry IDs; correct or retire obsolete entries explicitly. After that release, preserve the frozen 1.0 comparison and use subsequent ADRs to describe net enhancements, regressions, or compatibility changes relative to it. [ADR 0012](adrs/0012-deviation-baseline.md) owns that lifecycle; the [documentation contract](agents/documentation.md#deviation-catalog-maintenance) makes updating the catalog part of ongoing port work.
