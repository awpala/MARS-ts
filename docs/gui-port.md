# Venus GUI port mapping

This document maps the existing desktop interface to the requested MARS-ts 1.0 target, which retains MARS as its display name. The checked-in Java implementation is the behavioral authority. This preserves the original source mapping and remaining parity requirements; the [implementation guide](../IMPLEMENTATION.md) describes current browser behavior and validation boundaries, and the [deviation catalog](deviations.md) records where the implemented desktop deliberately differs from these legacy contracts. The [port plan](adrs/0000-port-plan.md) remains the milestone authority. The prepared [SVG assets and favicon](../static/README.md) are integrated by the Svelte GUI under `src/`.

The user requests a like-for-like translation: retain Java class names and responsibilities in corresponding TypeScript controllers where they carry logic, and use Svelte components for presentation. Do not replace existing behavior with a new IDE design. The initial browser layout should resemble the desktop, including compact controls, bordered panes, tables, menu ordering, and toolbar symbols. Adapt native file access and separate windows to browser file selection and dialogs inside the current tab. The root route opens directly into the main GUI: omit `MarsSplashScreen` and any splash or intermediary launch screen. Application implementation belongs under `src/`, with routes in `src/routes/` and components/controllers in responsibility-specific `src/lib/` directories.

`VenusUI` initializes the left vertical splitter at 75% editor/execution and 25% messages. Its width preferences depend on desktop screen size; in the browser, begin with the equivalent dominant left region and narrower register sidebar, and retain resizable dividers within the current viewport. `ExecutePane.setWindowBounds` supplies the exact internal initial proportions. The source, rather than unrelated web IDE conventions, determines default placement.

Toolbar order from `VenusUI.setUpToolBar`: New, Open, Save, Save As, Dump Memory, Print; Undo, Redo, Cut, Copy, Paste, Find/Replace; Assemble, Go, Step, Backstep, Pause, Stop, Reset; Help. Preserve separators and display Dump Memory only when dump formats are available. Select All exists as an action but is not added to the toolbar. Memory Previous / Next buttons use the two additional prepared SVGs.

The implemented toolbar adapts that order ([UI-0006](deviations.md#ui-0006-command-access-and-added-bulk-controls)): New, Open, Close All, Save, Save As, Auto Save, Import, Export, Export All, Dump Memory; Undo, Redo, Cut, Copy, Paste, Find/Replace, Show line numbers; Assemble, Go, Step, Backstep, Pause, Stop, Reset, Toggle all breakpoints, Clear all breakpoints, Exception Handler; Labels, Args, popup input, hexadecimal addresses, hexadecimal values, ASCII, Memory Configuration; Help. The run-speed slider follows only in Execute. Printing uses the browser command, and there is no Print or Exit action ([UI-P0006](deviations.md#ui-p0006-launch-printing-and-application-lifetime)).

## Browser adaptations and engine contracts

- File Open replaces `EditTabbedPane.openFile`'s `JFileChooser` with a same-tab local source-library picker. Import uses the browser file input to populate that library with complete `.asm` or `.s` text, matching the legacy `Extensions` setting and Open dialog filter case-insensitively, and also reads ZIP archives of those sources; a confirmed summary lists skipped items, and cancellation leaves source state unchanged. Includes resolve open buffers first, then committed library sources without claiming access to native directories. Assemble uses the active source and explicit `.include` directives; unrelated open tabs are not assembled. The assemble-all UI is removed and its saved preference is reset on startup. The engine retains its canonical multi-program assembly support.
- Save/Save As commit complete source text to the localStorage working filesystem. A persisted Auto Save toggle commits changed open buffers; synchronous workspace backups restore uncommitted text and tabs even when it is off. Export and Export All download portable files that keep a recognized `.asm` or `.s` extension, giving other names `.asm`, without changing dirty state. [ADR 0003](adrs/0003-browser-file-workflows.md) records these deliberate browser adaptations.
- Find/Replace, settings, exception-handler selection, memory configuration, help, About, unsaved-change prompts, and dialog syscalls render inside the current browser view. Preserve each action's choices and returned values; dialogs need focus entry, keyboard dismissal where appropriate, and focus restoration. No separate application windows.
- Settings preserve applicable fields and defaults from `Settings.java` / `Settings.properties`, including display bases, label visibility, popup input, extended instructions, delayed branching, self-modifying code, warnings-as-errors, start-at-main, and assemble-on-open. Label visibility, program arguments, popup syscall input, hexadecimal addresses, and hexadecimal values appear first in Settings in that order, sharing state and enablement with the retained toolbar buttons. The browser-specific Clear all outputs on Go and Prompt to clear all breakpoints follow Initialize Program Counter in the same group ([ADR 0008](adrs/0008-clear-outputs-on-go.md), [UI-0014](deviations.md#ui-0014-live-breakpoint-controls-at-finite-speeds-locked-at-maximum-speed)). Settings separators follow Values displayed in hexadecimal, Prompt to clear all breakpoints, and Self-modifying code; Exception Handler and Memory Configuration end the menu. Command-line integration remains excluded; GUI program arguments follow [ADR 0009](adrs/0009-program-arguments.md). Fonts, syntax colors, and runtime highlighting are editorial JSON presets bundled at build time, with no Editor/Highlighting settings dialogs ([UI-0005](deviations.md#ui-0005-fixed-editorhighlighting-presets-and-a-theme-choice)), and the assemble-all setting is removed. Every other legacy Settings entry is implemented. Browser persistence replaces Java Preferences for supported user preferences without making process-wide mutable state.
- The [Help module](../src/lib/help/README.md) owns the overview/About content and eleven adapted legacy articles, presented individually from the Help menu and together in the tabbed Help browser, each with a [Markdown companion](../src/lib/help/markdown/README.md) opened by Read Online. Help and About MARS remain first in the menu, with a divider before the added article entries. Articles preserve source credits and dates, identify current browser adaptations, and omit the obsolete printing postscript. The syscall reference has a bounded scroll area, sticky headers, alternating row bands, and bulleted notes. Code blocks offer Copy and Open as new file controls; generic dialog behavior remains shared outside Help.
- The engine owner exposes per-session register, memory, symbol, statement, diagnostic, and execution snapshots; actions for assembly/run/step/backstep/pause/stop/reset and cell writes; settings; breakpoints; and subscriptions returning unsubscribe callbacks, through `Globals` and the framework-free [RunController](../src/lib/venus/RunController.ts). The GUI never reimplements instruction, numeric, or assembler logic.
- The browser host supplies source lookup, asynchronous console input, syscall dialogs, MIDI tone output, cooperative scheduling, engine preferences, and entropy for unseeded random streams through the engine's host interfaces ([ADR 0004](adrs/0004-cooperative-simulation.md), [ADR 0014](adrs/0014-random-and-dialog-syscalls.md), [ADR 0015](adrs/0015-midi-web-audio-tones.md)). Runtime file and time services remain to be supplied with the unimplemented file, time, and sleep syscalls. Closing/replacing an IDE session cancels pending input and execution and releases every subscription. UI components own interaction state; engine sessions are not Svelte module singletons.
- Browser-reserved shortcuts ([UI-P0004](deviations.md#ui-p0004-keyboard-ownership-and-clipboard-permissions)), native printing and Exit ([UI-P0006](deviations.md#ui-p0006-launch-printing-and-application-lifetime)), storage persistence ([ADR 0003](adrs/0003-browser-file-workflows.md), [ADR 0007](adrs/0007-desktop-session-recovery.md)), execution scheduling ([ADR 0004](adrs/0004-cooperative-simulation.md)), and the editor implementation ([port plan](adrs/0000-port-plan.md#8-open-decisions)) are decided. The implementation order of the bundled tools remains open; the Tools menu lists them as disabled entries. Preserve legacy action meaning where the browser permits it; do not silently add dependencies or invent substitute behavior.

The root package and dependencies are installed. Desktop editing, debugging, Help, automatic exception-handler selection, memory configuration, memory dumps, random services 40–44, syscall dialogs 50–59, and MIDI services 31 and 33 are implemented.
