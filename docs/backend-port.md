# Backend translation plan and oracle evidence

The backend target is a direct translation of the checked-in Java implementation into framework-free TypeScript for MARS-ts 1.0. Preserve existing class names, method names, instruction definitions, algorithms, data tables, error messages, and observable behavior wherever the browser environment permits. This document retains the source analysis and dependency map that ordered the translation. The translated engine now lives under `src/lib/engine/`, and focused Java-generated method probes complement the CLI corpus. The P2 engine-core milestone in the [port plan](adrs/0000-port-plan.md) is complete; the [engine guide](../src/lib/engine/README.md) describes the implemented modules, and the remaining rows below identify what is still unported.

This is dependency ordering, not permission to implement disconnected pieces ahead of milestones. `InstructionSet`, `ProgramStatement`, assembler, and simulator have mutual type references; translate their contracts together where needed while completing one behavior unit with oracle evidence at a time. Engine modules belong under `/workspace/src/lib/engine/` (`src/lib/engine/` relative to the repository root) and never import UI code. The root `package.json` and configuration files reference the application under `src/`; there is no separate nested app package. Each module README identifies its Java mapping, state ownership, numerical conventions, and fixtures; extend those READMEs as the remaining units are ported. The [scope decision](adrs/0002-port-fidelity.md) records the user's direct-translation direction and initial browser substitutions.

## Necessary environment substitutions

Java's `Globals`, register files, memory, coprocessors, random streams, and settings are process-wide. Each browser simulator session must own its own instances while retaining the class responsibilities and method behavior. Shared instruction metadata can be immutable; machine state cannot be shared. Preserve session reset, assembly, run, step, backstep, and stop transitions instead of inventing new execution semantics.

Java `Observable` notices become explicit subscriptions with unsubscribe functions. Preserve the observable access information and order. The UI owns subscriptions and releases them when a view/session closes; the engine never references a component. `SwingWorker` and Swing callbacks require an execution adapter that yields to the browser and can await input, but instruction sequencing, delay slots, breakpoints, and undo records remain `Simulator` and `BackStepper` responsibilities. [ADR 0004](adrs/0004-cooperative-simulation.md) resolved the scheduling choice: the engine runs cooperatively on the browser main thread through an injected scheduler and asynchronous input services; no Web Worker is used.

`SystemIO` and syscall classes receive host interfaces rather than platform APIs. Source lookup, console input/output, syscall dialogs, MIDI tones, scheduling, preferences, and random-stream entropy are implemented this way; runtime file and time services will follow the same pattern when the file, time, and sleep syscalls are ported. Vitest suites and the browser supply distinct hosts to the same engine. File selection belongs to the browser UI; the assembler receives the selected source content and names. Dialogs appear within the existing browser view. Neither those adaptations nor SVG conversion belongs inside instruction execution or assembler code.

Java integer wrap, signed versus unsigned comparisons, HI/LO arithmetic, division rounding, and byte order are preserved explicitly. Use normalized 32-bit numbers and exact 64-bit representations, not floating-point multiplication for `long` results. Coprocessor registers retain raw bits; single-precision results round to float precision. Preserve Java's float/double print behavior and `java.util.Random` sequence, including seed treatment and bounded sampling. These are translations of existing behavior, not opportunities to substitute algorithms.

## Oracle evidence

The [oracle corpus](../tests/oracle/README.md) supplies original probe programs, explicit CLI/input cases, exact output bytes, exit statuses, provenance hashes, and a dependency-free regeneration/check runner. It exercises arithmetic and register boundaries, memory/directives, macro/include/pseudo assembly, branch settings, console syscalls, floating-point bits/printing, seeded randomness, heap alignment, program arguments, entry-point selection, error diagnostics, exit status, and bounded execution. The checked-in Java implementation generates every expected result through the isolated wrapper.

`node tests/oracle/run.mjs --check` runs in the `legacy` validation tier; it rebuilds the oracle before comparing all cases and requires neither npm nor the TypeScript implementation. The [core-program consumer](../tests/session/core-programs.test.ts) runs these same inputs through the translated engine and compares the captured console bytes, diagnostics, and machine observations, with the documented checkout-path normalization; GUI `Exit2` follows Swing rather than the launcher's process exit code. Oracle self-reproducibility alone is not evidence of TypeScript parity.

Dedicated probes now cover special floating-point conversion, CP0 exception-handler entry, Backstep and access ordering, self-modifying code, all memory configurations, and all six enabled dump formats. Services 40–44, 50–59, 31, and 33 are implemented and compared through the [random, Swing dialog, and MIDI probes](../tests/oracle/platform-syscalls/README.md); automatic handler selection and trap/`eret` execution have their own [workflow probe](../tests/oracle/exception-handler/README.md). Remaining gaps include exhaustive basic/pseudo variants, native multi-file project workflows, runtime file operations, time/sleep, audio timbre, and Tools. Extend probes with each remaining port; these captures do not establish exhaustive parity. No behavior divergence is proposed by this analysis. Ported source and copied data retain the original authors' copyright and MIT notice from [MARSlicense.txt](../MARSlicense.txt); these newly authored probes and analysis do not copy Java implementation text.
